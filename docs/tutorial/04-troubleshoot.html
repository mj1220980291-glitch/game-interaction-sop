报错先分四类

看到红字先别改 Markdown。大部分报错跟文档内容无关，跟进程、连接、模板有关。先定位在哪一层，能省掉一半折腾。

先判断是哪一类

工具列表里没有 render_v2_markdown_to_figma，也没有任何 figma_ 开头的工具，说明 MCP 服务根本没起来。这时候让人重开插件没有用。

工具都在，调用才报错，才继续往下查。看返回里的 code 字段，不要只看消息文本。

按现象查

工具列表里一个 figma 工具都没有

这是进程级失败，不是插件、不是模板、也不是 Markdown。两个典型原因：

  • 启动命令写错，进程起不来。常见是 spawn npx ENOENT，Node 不在 PATH 里。
  • 端口被别的条目占着。以前单独配过一个 figma-console 服务，它占住了 9223，引擎抢不到。

先把多余的 MCP 条目删掉，只留 figma-interaction-doc-engine，然后禁用再启用这个服务。

渲染一直失败，也看不到 figma 代理工具 V2_BACKEND_UNAVAILABLE

少了环境变量 FIGMA_BACKEND=figma-console。缺了它引擎不会拉起子进程。

补上这个变量，重启 MCP 服务，然后看工具列表里是不是多出了 figma_ 开头的工具。

明明开着 Figma，却说没有连接的文件 V2_BRIDGE_DOWN

连接插件没在要写文档的那个文件里运行。打开要写文档的那个文件，启动社区插件，保持窗口开着。

插件没装：在 Figma 顶部菜单进 Community，搜索本组上传的连接插件，Run 到当前文件。搜不到就问组里已经装过的人要插件页链接。

网页端就能跑，不需要装客户端。启动后调一次 figma_list_open_files，返回里有要写文档的那个文件才算连上。

文件读不到，或读到的不是你以为的那个 V2_TARGET_FILE_UNREACHABLE

两种常见情况：要写文档的那个文件没在 Figma 里打开，或者插件开在了另一个文件里。

把插件切到要写文档的那个文件。写文档和读设计稿，必须在同一个文件里。

模板节点对不上，或找不到模板根 V2_TEMPLATE_NODE_MISMATCH V2_ROOT_NOT_FOUND

要写文档的那个文件里那个 id 不是模板，或者干脆没有这个节点。

  • 核对模板节点 id 是不是 1:14。
  • 如果你的文件里模板放在别处，改用文件 key 加节点 id 的方式指定。
  • 项目已经编译过模板包的，改用模板包，不用再猜节点 id。
模板在另一个文件里，跨不过去 V2_TEMPLATE_OTHER_FILE V2_TEMPLATE_FILE_UNREACHABLE

Figma 不能跨文件克隆节点。模板文件和要写文档的那个文件不是同一个时，这条必然出现。

唯一的可靠解法是改用已发布的模板组件 key。要写文档的那个文件里不需要放模板，引擎按库引用去取。跨文件时不要反过来试文件 key 加节点 id，那条路走不通。

找不到项目模板包 V2_TEMPLATE_PACK_MISSING

四个查找位置都没有本项目的模板包。返回里会带一份候选列表，每个位置标明是没有文件、读不出来，还是缺字段。

  • 没有文件：正常。走库引用或同文件模式即可，不要为了消掉这条去手写一份配置。
  • 读不出来：删掉那份坏配置，或者按契约重写。
  • 缺字段：缺顶部、章节、簇三个 key 里的某一个。补齐，或者改用库引用。

手写模板包不是可接受的临场动作。它需要真实发布过的组件 key，写错只会换来下一条错误。要么用编译工具产出，要么用库引用。

用了 @职能 标记，渲染时报角色块不可用 V2_ROLE_BLOCK_UNAVAILABLE V2_ROLE_BLOCK_SET_NOT_IN_TARGET_FILE

Markdown 里有「@职能：」条目，但要写文档的那个文件里没有职能标记组件集，或者组件集不在要写文档的那个文件里。

  • 跨库：改用已发布的变体 key。
  • 同文件：确认组件集就在渲染要写文档的那个文件内。
  • 这次不需要标角色：把文风里的角色标注改成 never，一条都不写，就不需要这个组件集。

配置缺失时应该在渲染前就告诉你，不要先渲染再报错。没提前说的，回一句「先检查角色块配置」。

写完 Markdown，进不了下一步 V2_SIGNOFF_*

澄清没真正完成。四种具体报错：冲突没清零、还有待定问题、四个维度没全绿、声明文件不合法。文件不存在时报 V2_SIGNOFF_FILE_MISSING。

回去继续问，不要改声明凑数。校验只认四件事：冲突为空、待定为空、四个维度全为 true、版本号为 1。

Markdown 被拒，提示输入不合法 V2_VALIDATE_INPUT_SCHEMA V2_RENDER_INPUT_SCHEMA

结构没过硬校验。按这个顺序自查：

  1. 文件头四行是否齐全，顺序对不对。
  2. 第一个 # 是否只有一个。
  3. 「设计总览」是否只包含功能背景和核心交互两块。
  4. 章节序号是否从 01 连续，没有跳号。
  5. 每个语义簇第一行是否有角色标记。

如果模板包声明不支持簇分组，还要检查有没有四级标题。写了会在建画布前被拒。对应文件是项目里的 .interaction-sop/md-contract.md。

渲染成功，但有几张图没贴上 V2_W_FIGURE_ASSET_MISSING

这是提醒，不是失败。Markdown 里声明了配图，但资产表里没有这一项，槽位保留成灰色占位。

逐条看提醒里的章节、簇和键，补上来源，或者明确说这次不要这张。用户说过「配图先不贴」的，后续不再提醒。

报错里出现 ws://localhost:923x，数字每重启一次加一

端口漂移，不是插件问题。旧引擎进程没退，僵尸进程占满了 9223 到 9232。

新版引擎会自己抢回 9223 并重拉子进程。仍失败时返回 E_BRIDGE_PORT_CONFLICT，详情里有端口和各进程号，照着清理即可。处理办法写在 packages/figma-mcp-server/docs/INSTALL.md 的重启段落里。

不要反复重开插件，那样只会多占一个端口。

不报错但会卡住的三件事

  • 编译完必须重启 MCP 服务进程。只新开一个对话不够。CodeMaker 里是扳手图标，MCP Servers，禁用再启用。
  • 更新 skill 要加 --force，否则不会覆盖旧文件。命令是 npm run install-skill -- --agent codemaker --force。
  • 同时开着两个 Figma 窗口时，确认插件开在你想要的那个文件里。判断方法：让 AI 列一次打开的文件，看列表里是哪个。

没收录在这里的错误

这份清单只收了安装和第一次运行最常撞的。其余错误码在两处：

  • packages/figma-mcp-server/docs/figma-mcp-pitfalls.md，按坑分类，带引擎的防护说明。
  • packages/skill/references/anti-patterns.md，八条实战反模式，每条带自检问题。
从老版本升级过来的人注意

以前给 Figma 单独配过一个 figma-console MCP 服务的，现在要删掉，只保留 figma-interaction-doc-engine。两个都留着会抢端口，表现为随机连不上。
