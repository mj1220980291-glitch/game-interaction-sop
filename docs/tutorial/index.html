一份需求，变成 Figma 里的交互文档

这套东西把「策划提需求」到「Figma 里排好的交互文档」之间那段活，固定成一条流程。你说清需求、给图、审稿，AI 按规范写文档，再通过引擎写进 Figma 模板。

它做什么

三步，每步都有明确产物。第一步和最后验收需要你参与，中间由 AI 完成。

谁在做什么

四方的分工要分清。搞混了就会出现「以为是工具的问题，其实是文件没打开」这类误会。

它是怎么搭起来的，单独画成了一张架构图：docs/architecture/index.html。

从哪开始

第一次用 装了就能跑 四步装好，拿一份真需求走完整个流程。 交付前 验收清单 照着勾，勾完就是能交的文档。 要长期用 项目资产 文风、模板、模式库是什么，怎么配、怎么维护。
