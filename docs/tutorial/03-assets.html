文风、模板、模式库

这三样东西决定这份文档「读起来像不像你们组写的」「排出来是不是你们要的版式」「下次同类需求能不能少问几轮」。先讲它们是什么，再讲怎么配、怎么维护，最后是文件放哪。

先说结论：不配也能用

你没配会发生什么
文风 用 skill 自带的默认文风。随安装一起到位，不需要复制任何文件。
模板 用内置默认模板地址。第一次跑通不用碰模板。
模式库 检索这一步直接跳过，不影响任何阶段。

所以新人第一周不需要建任何文件。需要配的时机是另一个：你们已经有一份「组里都认」的写法，或者这个项目的模板和默认模板长得不一样。

三样东西分别是什么

怎么配

资产最小配置动作谁做
文风 想有项目基线：把 packages/skill/references/style-default.md 复制成 .interaction-sop/style.md，改成你们的写法。个人文风不用建，第一次沉淀时自动生成。 人改基线，AI 生成个人文风
模板 默认模板够用就不做。项目版式不同：按编译流程做一套，登记后这个项目自动用它。 人（编译中有一处必须人点发布）
模式库 没有就先空着。想建：让 AI 读两三份历史文档做冷启动，生成第一批条目。 AI 起草，你确认

怎么维护

资产维护方式频率
文风 交付时你改过的表述，AI 列成清单问你要不要收，收了才写进去。基线文件 style.md 永不自动写。 有改动才有，不是每份都有
模板 模板改了就重编，用 -v2 后缀生成新组件，不原地改、不删旧的。 模板变更时
模式库 按风险分级增量维护：新东西才建条目，旧条目只在结论变了时改。 每轮结尾自动判断

文件都放在哪

项目级文件统一放在项目根的 .interaction-sop/ 目录。七项，各有各的归属。

文风：怎么写由它定

每份文档开始前挑一份，先命中先停，中途不换。你说「换成某某那份」，从下一段输出开始生效。

目录里有什么行为
存在任意 style_名字.md 每份文档开始前问你一次用哪份，默认指向你的 style_own.md。
没有带名字的，有 style_own.md 直接用，不问你。
只有 style.md 直接用，不问你。
一个文风文件都没有 加载 skill 自带的默认文风，静默继续。

一份文风长什么样

文件头是三组开关，下面是可选的范例段。

---
schema_version: 1
name: 局内交互组
verbosity:
  level: terse
  bullets_per_cluster: 3-5
role_annotation:
  mode: selective
  when:
    - 数值阈值 / 配表字段
    - 服务端逻辑但界面有可见结果
  never:
    - 通用交互流程
wording:
  tone: 直述
  person: 无人称
  sentence: 短句
  terms:
    - from: 警官蛋
      to: 治安官
  banned:
    - 尽量
    - 建议
---

## 示例

- 好：按住左键锁定朝向，按住期间移动不改变角色朝向
- 坏：玩家可以尝试按住鼠标左键来对朝向进行锁定

三组开关的范围：verbosity 管写多细，role_annotation 管什么时候把一条规则写成「@职能：」条目，wording 管语气、人称、句长和术语替换。

文风管不到的地方

引擎的硬校验和状态行规则不受文风影响。哪怕全组都习惯那样写，只要违反，仍然拒绝渲染。两者撞上时，先满足校验，再谈文风。

想用别人的文风

把对方给的东西丢给 AI：一段文字、一份旧文档、一个 Figma 链接都可以。它会反推成上面那三组字段，出草案让你确认，确认后存成 style_名字.md。同名文件已存在时先备份成 .bak。

想把你的给别人

让它把文件完整内容打印出来，或者写成独立文件带走。不改字段，也不擅自删掉你觉得敏感的说法。

模板：长什么样由它定

模板包把项目模板编译成共享库里的四个部件，登记之后这个项目就用它。四个部件分别是顶部、章节、簇、结尾。

从项目模板到可用，五步

登记产出 ~/.game-interaction-sop/templates/<项目名>.json，里面只有组件 key 和能力说明，不含节点。项目目录里再留一份 .interaction-sop/template.json 指过去。

引擎按这个顺序找模板包

  1. 环境变量 GISOP_TEMPLATE_PACK 指向的路径。
  2. 当前目录的 .interaction-sop/template.json。
  3. ~/.game-interaction-sop/templates/<GISOP_PROJECT>.json。
  4. ~/.game-interaction-sop/templates/default.json。

四个都没有，报 V2_TEMPLATE_PACK_MISSING，并把这四个位置的检查结果一起返回。看到这条不用猜，看候选列表就知道差在哪。

四处会卡住

粘错、漏粘，或粘了张截图 V2_COMPILE_STAGED_PART_MISMATCH

编译认的是节点 id，名字只用于核对。粘错项目、少粘一块、把截图当模板粘进去，都会在这一步被拦下。

按提示重粘。粘完不要改名、不要摆位置。

编译完了，但没人在 Figma 里发布 V2_COMPILE_NOT_PUBLISHED

编译只是把组件造出来，没发布就取不到 key。去库文件里走一遍 Assets，管理库，发布变更。四个部件和全部零件都要在列表里。

另一种情况：发布过，但 key 变了。同样重发一次。

组件名以 _ 或 . 开头，发布不出去 V2_COMPILE_UNPUBLISHABLE_NAME

Figma 会把这类命名归进隐藏组，不会发布。改名重跑即可。

另一种触发：项目名里带了 : / \ * ? " < > |。项目名会变成配置文件名，这些字符写不出来。像 1:14 要写成 官方1.14。

冒烟跑不起来，或者卡到超时 V2_COMPILE_VERIFY_UNAVAILABLE

冒烟要在空的沙盒文件里跑。在源项目文件里跑，部件可能还依赖源文件里的组件，导入会成环，实测三十秒超时。在库文件里跑则永远成功，测不出到底发布没有。

先确认插件开着，再把校验文件换成一个空文件。

重编只能追加

模板改了重新编译，用 -v2、-v3 后缀生成新组件，新 key 覆盖配置。不要原地改，也不要删旧组件，否则已经交付的文档会连带失效。

一个项目只能挂一套模板。需要两套排版时，只能另开项目目录。

模式库：可复用的写法

一个条目一个文件，放在 .interaction-sop/patterns/，同目录还有索引和偏离记录。条目里记的是这类需求当时定下的结论、依据和适用范围，格式见 packages/skill/references/pattern-schema.md。

开新需求时先检索，命中了就拿来当起点，少问一轮。没有库就跳过，不报错。维护由最后一个阶段按风险分级做：新东西才建条目，旧条目只在结论变了时改。

写法边界：md-contract.md

登记时会一并返回这份文件的内容，由调用方落盘到 .interaction-sop/md-contract.md。它由模板能力推导，写明这个项目能写哪些结构。

模板能力意味着
不支持簇分组（clusterGroups: none） Markdown 里不能出现四级标题。写了会在建画布前被拒绝。
不支持设计总览（overview: none） 不能写「设计总览」那一节。

最容易在两种场合踩到：从别的项目抄写法，或者照着附录的完整示例写，而本项目模板是精简版。改 Markdown 之前先翻一眼这个文件。
