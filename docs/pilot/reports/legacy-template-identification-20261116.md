## 4. 歧义与最终口径（2026-11-16 用户确认）

### 4.1 选哪一章当基准 → 只取 A
A / B / C 三种样式同时存在，宽度 4694 与 4600 混用。**决定：只清洗 A 样式（`173:15935` / `173:16252`）；B（`173:16143`）与 C（`173:15881`）只作歧义记录，不静默改造。**

### 4.2 图片放哪一层 → 章节主图
旧稿一图对「一个状态」（章节级），引擎 parts 渲染按「一个簇一个配图槽」。**决定：把章节 `sect > img` 映射为章节主图占位（`mainImage`），簇级 `figure` 设 `none`；md 里的 `配图：` 条目会得到丢弃告警，属预期。** 不改布局、可逆；按簇拆图作为后续能力，不在本次。

### 4.3 职能标记要不要沿用旧视觉 → 换标准组件
旧：`注意` 组件集（红/紫 pill + `GUI注意` 文案）。**决定：不保留旧视觉，替换为引擎标准 `职能标记=<角色>` 变体，与已验收的燕云链路一致。** 旧稿仅出现 GUI/程序 两种角色；其余角色按需新增变体，不臆造。

> 复核修正（2026-11-16）：簇级 `tag` 容器在 5 个簇中有 4 个是隐藏的，只有 `173:15981` 可见；截图中看到的 pill 多数属于图片内容。因此本决定更准确的说法是：**旧稿实际上没有可用的可见职能槽**，清洗时按标准组件新建，而不是"改造旧 pill"。
