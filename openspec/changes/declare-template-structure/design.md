## 上下文

引擎当前把「模板长什么样」写在代码里：槽位名常量（`template-slots.ts`）、4 部件模型、8 项能力枚举，以及若干结构性硬假设（正文同宿主、标号需 `气泡` 容器 + 母版、职能需 `职能标记=` 变体集）。接入新模板 = 把模板改造成这套形状（编译期改名 / 收编 / 空壳化 / 补容器），契约外的结构不会被渲染，也不会报警。

燕云真机对比（渲染 `201:4247` vs 原稿 `201:5487`）给出了具体损失：顶部 4 块缺失、角色标签组件集不符、标号形态不符、正文列宽偏移。这些问题不是单点 bug，而是「结构知识在代码里」这一架构选择的必然结果。

本设计的核心命题：**把结构知识从代码搬到 pack 声明**，让引擎变成「按声明执行」，从而新模板接入不再需要改造模板本身。

## 决策

### D1｜声明是唯一运行时路径，老 pack 靠「默认声明生成」兼容

- pack 有 `layout.blocks` → 直接使用。
- pack 无 `layout`（`schema_version: 1`）→ 运行时用 `default-layout.ts` 以现有 8 项能力为输入生成一份**等价声明**，之后走完全相同的路径。
- 运行时不保留「按名字查找」的第二条分支；`template-slots.ts` 的常量只作为生成器与编译期使用。
- 永久兼容：老 pack 不要求迁移；`schema_version: 2` 只是「带显式声明」的标记。

**备选**：一次性迁移所有 pack（否决：用户要求永久兼容层；且二跳迁移会把老文档与老 pack 同时推到风险面）。

### D2｜声明只描述「结构与槽位」，不描述样式与几何

声明表达四类块与槽位映射：

```ts
interface BlockDecl {
  id: string;                       // 稳定标识，进 stamp
  part: 'top' | 'chapter' | 'cluster' | 'footer';
  repeat?: 'sections' | 'clusters' | 'none';   // 循环来源（章节 / 簇 / 单次）
  slots?: Record<string, SlotDecl>;             // text / instance / group 槽位
  list?:  { template: string; source: 'overview' | 'bullets' | 'revisions' };  // 克隆行
  table?: { template: string; columns: Record<string, string> };              // 表格列 → 槽位名
  roles?: { componentSetKey?: string; labelSlot: string; variants: Record<string, string> }; // 角色 → 变体
  badge?: { mode: 'container' | 'instance' | 'none'; container?: string; labelSlot?: string };
}

interface SlotDecl {
  kind: 'text' | 'instance' | 'group';
  /** 部件内定位：名字（归一化后）或 nodeId；两者二选一 */
  name?: string;
  nodeId?: string;
  /** 写入来源：md 字段 / IR 节点 / 常量 */
  source: string;
}
```

- 样式、坐标、字体、间距**不进声明**：它们属于模板部件本身（编译保留），声明只回答「这个节点承载什么数据」。
- 不允许通过声明改样式 —— 避免声明变成第二套渲染器。

**备选**：把条件显示（`visibleWhen`）、缺省值、样式覆盖也放进声明（否决：表达力膨胀，且与「结构唯一」目标无关，可以后按需加）。

### D3｜组件形态直接进声明（角色 / 标号）

- `roles`：声明「角色 → 变体 key」映射与标签槽位名，取代代码里对 `职能标记=` 前缀的假设。燕云这类 `职位=GUI注意` 组件集因此可以原样使用。
- `badge`：`container`（克隆母版摆格子）或 `instance`（标题行里的 `序号` 组件实例，只改实例内数字），或 `none`。
- 能力表保留为**默认声明生成器**的输入：`roleAnnotation` / `badgeSlot` 等枚举 → 生成 `roles` / `badge` 片段。运行期不再直接读枚举。

**备选**：能力表当预设、声明可覆盖（否决：引入优先级规则，回到「双源头」；用户明确避免）。

### D4｜md 契约新增三段可选内容

```md
## 需求概述

### 小标题一

正文……

### 小标题二

正文……

## 修订记录

| 修订日期 | 修订人 | 修订内容 | 修订原因 |
|---|---|---|---|
| 2026-11-18 | 苗儿 | 初稿 | — |

## 审核情况

审核人：张三
UI：李四
```

- 三段均可选；缺失时对应块**隐藏**（不保留模板占位文案）。
- 与 `## 设计总览` 并存：总览仍属 `overview` 能力（官方 1.14 形状）；概述是独立块，两者不互相替代。
- 修订记录必须是 Markdown 表格（用户已定），首行为表头；列名固定为四列，顺序可任意但需齐全，缺列报硬错误。
- 审核情况为 `键名：值` 行，键在声明里映射到槽位（不写死为「审核人 / UI」）。

### D5｜编译期生成声明草案并写回 pack，人工确认

- `figma_compile_template(phase=compile)` 在收编 / 空壳化 / 归一化之后，扫描部件结构并生成 `layout.blocks` 草案：
  - 已知形状（抬头 5 槽、章节、簇、配图槽…）按规则生成；
  - 结构外的块（跟进人 / 修订记录 / 审核 / 概述）按「frame 名 + 内部文本名」给出候选声明，标记 `draft: true`；
- 草案写回 pack（`schema_version: 2`），`draft` 字段提示人工确认；确认后去掉 `draft`。
- 编译期校验：声明里出现的 `name` / `nodeId` 在部件中不存在 → 记 gap；渲染必失败的声明（如 `table` 无 `template`）→ verify 阶段硬失败。

### D6｜对账标识：`blockId/slotId + 行序`，老 stamp 归一化

- 新 stamp 记录 `blockId/slotId/行序`，不再记录名字路径。
- 老文档 stamp（名字路径）通过 `layout-identity.ts` 归一化为声明标识；映射不唯一时（同名节点多处）报软警告 `W_LAYOUT_IDENTITY_AMBIGUOUS`，该条目按「保留」处理，不自动删。
- 同步计划只在声明 id 空间内比对，避免燕云真机出现过的 `02/1/-` 无主条目误删。

### D7｜单一告警源

- 新增一组 `V2_W_TEMPLATE_LAYOUT_*`：`SLOT_MISSING`（声明有、部件没有）、`IDENTITY_AMBIGUOUS`、`BLOCK_HIDDEN`（有数据但块未声明）等。
- 老的 `V2_W_HEADER_SLOT_MISSING` 等保留为**同一来源的兼容别名**（同一判定只发一条，按 pack 版本选码），不新增第二个判定点。
- `mdContract` 文案统一从声明生成（含新三段），不再一半读能力表一半读名字常量。

### D8｜迁移与灰度

- 生产不保留双渲染路径；等价性靠测试保证：同一 pack「带声明 / 由生成器生成声明」渲染结果逐节点一致（`layout-equivalence.spec`）。
- 老 pack 走生成器路径；新编译产物走显式声明路径；两条路共用同一渲染器。
- 真机回归范围：官方 1.14、蛋仔、燕云、旧稿清洗四套模板各跑「渲染 + 两次同步零变更」。

## 待讨论（开发前需要确认）

1. **段落缺失时块的默认行为**：当前设计为「隐藏」。是否需要对某些块保留模板占位（例如审核情况未填时仍显示空表）？
2. **表格行增删策略**：md 行数多于/少于模板行数时，是克隆/删除行（与正文条目同策略），还是固定行数只覆盖？建议与正文一致。
3. **同一部件复用**：多个 block 指向同一 `componentKey`（如顶部三块共用抬头部件）是否允许？建议允许，但声明里必须给不同 `id`。
4. **`repeat: clusters` 的编号/标号落点**：`badge.instance` 形态下，序号实例在标题块内，位置由部件决定；是否需要声明「编号是否随簇序号」以外的编号策略（如章节内连续）？
5. **声明草案的人工确认流程**：是「编译输出 draft → 人改 pack → 再跑 verify」，还是提供单独的 `confirm` 阶段工具？

## 风险

- 声明本身成为新的「可能写错的东西」→ 必须由编译生成草案 + 校验，不鼓励手写。
- 渲染/同步的测试面显著扩大 → 以等价性测试 + 四套模板真机回归兜底。
- 若声明 schema 没一次定稳，后续演进需要 `schema_version: 3` → 首版只上「结构 + 槽位 + 四类块 + 组件形态」，其余按需再加。
