## Context

渲染分两半：一半是把部件克隆进文档（样式随节点走，不用管），另一半是**算**出来的东西——部件怎么排、标号摆哪儿、占位用什么灰、章节宽度兜底多少。后半段今天全靠常量：

| 量 | 现在 |
|---|---|
| 部件间距 | `PARTS_GAP = 0` |
| 主图基准 | `MAIN_IMAGE_SIZE = 1920×1080` |
| 标号网格 | `DEFAULT_BUBBLE_GRID` 8 个固定点 |
| 章节宽度兜底 | `2209` |
| 占位灰阶 | 只按 `docBackground` 算，取不到就 `#F5F5F5` |
| 文档底色 | 只能人填 `docBackground` |

实测后果：官方1.14 重编后渲染成白底白字（模板深底 `#1A1A1A`），蛋仔 1200×719 的主图上标号按 1920×1080 换算后挤在一列。

## Goals / Non-Goals

**Goals：**

- 这些量在编译期从**产物部件**实测，写进 `pack.geometry`
- 渲染期优先用包里的值；包缺 `geometry` 时行为与今天完全一致（老包不受影响）
- 采到的值必须跟着模板重编一起更新，不能靠手填

**Non-Goals：**

- 不采集字体、行高、字重（字体归一化是另一件事）
- 不采集单个簇内部的 padding / itemSpacing（那些随克隆节点走）
- 不做「按内容自适应的间距」（渲染仍按模板固定间距排）

## Decisions

### D1 · 采集点在「产物部件」，不在源模板

编译完成后，库文件里已经有三个**已经归一化**的部件组件，直接量它们最准（源模板里可能有没被搬运的块）。

- `chapterWidth` / `mainImage` / `placeholder` ← 章节组件里的 `主图占位`
- `bubbleGrid` / `badgeSize` ← 章节组件里 `气泡` 的 `标号/N`（相对主图左上角归一化到主图尺寸）
- `rootGap` ← 章节组件自身的外边距（`paddingTop/Bottom`）；取不到就 0
- `docBackground` ← 源模板根节点填充；编译参数仍可覆盖

### D2 · 网格存「比例」，不存像素

`bubbleGrid` 的坐标按**主图比例**存（0–1），渲染时再乘主图实际宽高。这样模板主图改尺寸（`1920×1080 → 1200×719`）网格自动跟着缩放，不需要重采。

例外：主图尺寸本身也存（`mainImage{width,height}`），用于「模板没带标号、需要按默认网格造」的场合。

### D3 · 缺省即现状

`geometry` 每项都可缺省，缺了就用手里的常量：

| 字段 | 缺省 |
|---|---|
| `docBackground` | `#FFFFFF` |
| `chapterWidth` | `2209` |
| `mainImage` | `1920×1080` |
| `placeholder` | 按 `docBackground` 亮度算的灰阶（现有逻辑） |
| `bubbleGrid` | `DEFAULT_BUBBLE_GRID` |
| `badgeSize` | `48×48` |
| `rootGap` | `0` |

### D4 · 采集失败不阻塞编译

某个部件读不到（比如气泡缺失）就少采一项，记 `gap` 而不是让整次编译失败——几何是优化，不是正确性前提。

## Risks / Trade-offs

- **[老包无 geometry]** 行为不变，但观感问题依旧 → 文档里写明「重编一次即可」
- **[按比例存网格，模板本身网格不均匀]** 比例表达仍然精确（就是 x/width），不会失真
- **[采到的占位色是深色模板的灰]** 浅色模板沿用同一套逻辑，仍以模板自带色为准，比现在靠亮度猜更准
- **[章节宽度取自产物，重编后可能变]** 这正是想要的：宽度是模板身份

## Migration Plan

1. 先落 schema + 采集 + 写 pack（渲染不读）→ 老路径零影响
2. 再让渲染读 `geometry`，缺省回落
3. 真机重编蛋仔 + 官方1.14，对比渲染前后
4. 回滚：`geometry` 是可选字段，删掉即回旧行为

## Open Questions

- `rootGap` 到底该不该采：部件自带留白时它为 0，没自带时才需要；现在是两者都不明确，先按「章节组件的 paddingTop/Bottom」采，实测不够再补
