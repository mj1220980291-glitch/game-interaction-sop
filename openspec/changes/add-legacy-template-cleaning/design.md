## 决策

### D1｜识别证据按四类并列，命名不单独决定语义

判定部件只用四类证据：命名、局部层级（父子/兄弟）、重复结构、相对位置与尺寸，再叠加文本与截图。`cell_comment` 实为说明簇、正规模板自身也带审核与示例日期——这两条现场都推翻过"名字像什么就是什么"。

能力项（overview / clusterGroups / badgeSlot / numberBadge / roleAnnotation / figure / hiddenPool / column）逐项给证据；契约缺省与实测推断分开写。同一能力存在多个有效样式时全部列出并标冲突，**不静默混搭**。只有证据互相矛盾且截图也判不了时才找用户确认一次。

### D2｜隔离副本：整段外壳 + 最小代表集 + 生成区幂等

- 复制单位是**整章外壳**（卡片、圆角、底色、内边距、标题层级），不是内部 sect；`8.9a` 之前正是只搬了内部结构，导致外壳丢失。
- 最小可见集：1 章 + 1 状态 + 1 簇；独立部件另放，不与文档内容混排（避免"重复样板当内容"）。
- 每次执行写入一个明确命名的生成区；重跑替换该区内容，不追加。失败只删本轮生成资产，源内组件与用户资产一律不动。
- 原稿只读：所有写操作都落在副本 fileKey / 副本节点上，回执记录源→副本映射。

### D3｜清洗口径：可见文字、图层名、链接、图像填充一起查

替换：标题 / 状态名 / 正文 / 人员 / 日期 / 联系方式 → 明确占位（如 `待补充`、`状态说明占位`）。
图像：主图与业务配图 → 等尺寸中性矩形 + `配图占位：<描述>`；**业务图即使是组件实例也要换**，不能因为类型是 INSTANCE 就放过（真机有过漏清）。
链接：清除指向具体工单/个人主页的目标，只保留占位文本。
移除：审核记录、历史版本、隐藏旧稿；保留：标志、固定操作说明、必要职能标签、可证明有用途的隐藏样式母版——每项保留都要写依据。
字体：副本与编译产物统一 `Noto Sans SC`；保留字号/字重层级/颜色/排版，替换引起的换行与尺寸变化必须截图核对；原稿字体不动。

检查覆盖面：节点名、`characters`、`hyperlink`、`fills` 四处都要查，不能只改屏幕可见文字。

### D4｜槽位归一化后必须真编译，改名不算通过

归一化只在不破坏布局的前提下做：簇的 `Number` / `#Title_Main` / 正文（`正文/规则`）/ 职能载体 / 配图 GROUP，章节的 `#Name` / 主图占位 / `Text` 说明栏必须能定位。

但"改完名字能定位"不等于能编译：嵌套正文是否被支持、图槽能否被识别、职能变体能否解析，都要以**真实 compile 报告**为准（`phase=compile` 干跑通过只代表计划成立）。清洗结果必须依次走过 compile → 人工发布 → 独立沙盒 `phase=verify` → 渲染 → 同步，前一阶段通过不替代后一阶段。

### D5｜章节示例簇按结构清理，不靠 nodeId

parts 渲染时，章节子树里出现"既不是本轮生成的簇、也不是说明栏/主图/标题/编号槽位"的样板簇（特征：含 `簇标题`、`正文占位`、多个 `职能标记=*`、`配图占位`）应当整体移除或隐藏。判定基于结构特征与 `caps`，不写死 nodeId、页面名或项目名。

保留边界：`状态说明` 这类 foreign 说明栏继续保留（现状 `preserved` 已按 foreign 处理）；本轮真实簇、气泡、编号一个都不动。清理失败只记软警告，不中断渲染。

与 `sop-sharing-readiness` D10 的分工：D10 管**簇内**职能行按 md 角色取舍（已实现并真机通过）；本决策管**章节层**的示例簇整体。

### D6｜交付形态：先固化流程，再决定要不要暴露工具

先把流程固化为可重复执行的脚本 + 引擎能力，产出结构化回执；暂不新增 MCP 工具名、不改 `figma_compile_template` 参数面。等实证稳定、外部团队真的要走这条路时，再单独立项决定工具化形态。理由：清洗的判别逻辑还在收敛，过早定型接口会把错误固化。

## 口径决定（2026-11-16，用户确认）

1. **基准章节只用 A 样式**（`173:15935` / `173:16252`：4694 宽、标题 + 状态 TEXT + `sect`(左图 2400 + 右 `comment_list` 1974) + `cell_comment` 簇）。B（`173:16143` 无状态、无 sect 命名）与 C（`173:15881` 4600 宽旧修改块）只作为歧义记录，**不静默改造**。
2. **图片放在章节层**：旧稿 `sect > img`（一个状态一张 2400 宽）映射为**章节主图占位**（`mainImage`），簇级 `figure` 置 `none`。md 里的 `配图：` 条目会得到 `V2_W_FIGURE_DROPPED` 级告警，属预期。不改布局、可逆。
3. **职能换成引擎标准组件**：旧 `注意` 组件集（`职位=GUI注意/程序注意`）不保留视觉，清洗时替换为引擎标准 `职能标记=<角色>` 变体，与已验收的燕云链路一致。旧稿只出现 GUI/程序 两种角色，其余角色按需新增变体，不臆造。

## 真编译首批结论（2026-11-16，只跑 `write:false` 干跑）

对清洗副本 `205:42223` 做槽位改名后（`#Name` / `主图占位` + `主图占位文案` / `Text` / `说明块01` / `#Title_Main` / `正文/规则`），`phase=compile` 的第一条错误是：

```
V2_COMPILE_STAGED_PART_MISSING：_staging 页上缺「顶部」部件（top）
```

说明三件事：

1. **旧稿不是四部件结构**：`173:15842` 是整篇文档（抬头 + 正文 + 结尾），而 compile 需要 `top / chapter / cluster(/footer)` 四个独立 staged 部件。清洗流程必须显式产出四件，不能指望"整篇改个名就能编译"。
2. **头部槽位需要新建而不是改名**：引擎要 `文档标题 / 设计师名称 / 需求组名称 / 易协作单号链接 / 更新时间` 五个 TEXT 槽，旧稿抬头只有 Logo + 标题 + 5 个人员/入口 pill 实例。这是"加结构"，超出 D4 原定的"只改名不改结构"，需要在口径里补一条。
3. **编号槽也可能改不动**：旧稿编号 Text 在 `Tag` 实例内部（`I205:42252;204:2935`），实例子节点不能改名，`CLUSTER_SLOTS.number` 只能靠 detach 或新建 TEXT 满足。这也是"加结构"。

因此 D4 的"只改名不改结构"应修正为：**优先改名；当契约槽位在实例内部或旧稿根本没有时，允许新建最小槽位节点（并记录），仍禁止改布局/尺寸/层级顺序。**

## 风险

| 风险 | 缓解 |
|---|---|
| 识别靠猜、清洗不彻底 | 四类证据 + 四处检查（名/文本/链接/填充）+ 截图核对，回执逐项写依据 |
| 清洗把模板身份也洗掉 | 保留清单显式列出（标志/操作说明/职能标签/隐藏母版），并写依据 |
| 归一化破坏布局 | 只改名不改结构；发现必须改结构时停下来记歧义，不猜 |
| 章节示例簇误删真实内容 | 结构特征 + 排除槽位白名单；删除前先隐藏，截图确认后再定策略 |
| 反复执行导致副本膨胀 | 固定生成区、重跑替换；失败只清本轮 |
