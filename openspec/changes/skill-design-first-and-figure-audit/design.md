## Context

SOP 当前 Phase 1 的「入场材料识别」已经区分路径 A（图先行）与路径 B（策划文档先行），但**开口顺序**仍是策划文档优先：description 与第一回合话术都把策划文档当默认入口，路径 A 只在用户"恰好带了图"时才启用。用户希望主动引导先给设计稿。

配图侧：md v2 已有 `配图：` 语法与 W3 规则（配图紧跟所说明的规则、状态类簇一态一图），引擎已实现三态（filled / placeholder / hidden）并返回 `summary.figuresPlaceholder` 与 `V2_W_FIGURE_ASSET_MISSING`。缺的是 skill 侧两个动作：**写 md 时默认给每簇配图**、**渲染后截图核对并把缺图清单交回用户**。

约束：本次只动 `packages/skill` 的流程文档与版本号，不改引擎代码、不改 md v2 语法、不加新 MCP 工具。

## Goals / Non-Goals

**Goals:**

- Phase 1 第一回合先问设计稿（图 / Figma 链接），有图即按图提问；明确无图才转策划文档
- Phase 2 产出的每簇默认带配图意图（允许显式"本簇无配图 + 理由"）
- Phase 4（含同步模式）结束后做一次配图审计：截图 + 缺图清单 + 明确提醒用户手动补图
- 三处描述（SKILL.md / phase 文件 / skill description）口径一致，版本升到 `2.3.0`

**Non-Goals:**

- 不把设计稿设为硬前置门禁（用户选的是"只调顺序"）
- 不改引擎的配图三态判定、不加新告警码
- 不要求审计阻塞交付，也不在审计失败时自动重渲染
- 不替代 Phase 5 的文风收口，不新增 Phase

## Decisions

### D1 · 只改引导顺序，不改门禁

Phase 1 第一回合的标准结构改为：

```
我先确认材料：这个需求有设计稿吗？
1. 有图 → 直接发图片 / 给 Figma 链接（指向具体界面节点即可），我按图组织问题
2. 还没有 → 发策划文档，我按文档梳理，必要时提议先画一版界面草稿

（无图也照样往下走，不会卡住流程。）
```

- 有图 → 直接进路径 A，策划文档降为规则补充源（现有行为不变，只是入口从"被动识别"变"主动索要"）
- 无图但有文档 → 路径 B 不变，仍 MAY 提议画草稿
- 无图无文档 → 按现有"口头需求"路径问 1-3 个问题
- **完成条件不变**：4 维度 + `unresolved_conflicts` 清零仍是进入 Phase 2 的门

替代方案：把设计稿设为硬前置（无图不生成文档）——被否决，会挡住只有策划文档的常见场景。

### D2 · 配图默认项落在 Phase 2，不落在 Phase 3

"每簇默认配图"是**写 md 时**的产出规则，放 Phase 2；Phase 3 只负责把已有 `配图：` 条目映射成 `asset_map`，Phase 4 只负责渲染与审计。

- 默认规则：每簇 SHALL 至少一条 `配图：`，除非整簇无任何可指认的视觉对象（纯服务端规则 / 纯数值 / 纯环境演出）
- 例外写法：`- 配图：无（理由：本簇均为配表数值，界面无可指认对象）`，用户可推翻
- 自检清单加一条：`[ ] 每簇配图已覆盖（或写明无配图理由）`
- 与 W3 的关系：W3 管"配图放在哪"，本规则管"有没有配图"，两者叠加

替代方案：在 Phase 3 强制索要配图——被否决，Phase 3 拿不到未写进 md 的配图条目。

### D3 · 配图审计 = 引擎统计 + 截图目视，两层交叉

审计在 Phase 4「结果 A 成功」与「结果 D 同步完成」之后执行，步骤固定：

1. **读权威统计**：`summary.figuresPlaced` / `summary.figuresPlaceholder`，以及 `warnings` 里的 `V2_W_FIGURE_ASSET_MISSING` / `V2_W_FIGURE_FILL_FAILED`
2. **截图核对**：对每个 `## NN.` 章节用 `figma_capture_screenshot`（多部件产物截该章根帧；老结构截章节节点）取图，肉眼核对"正文旁是否还有灰板 / 虚线占位"
3. **合并清单**：以引擎统计为准，截图用于发现统计之外的视觉异常（占位被误判 filled、图片被裁切、hidden 该显示却没显示）
4. **输出提醒**，不阻塞交付

清单格式：

```
配图审计（截图核对）：
| 章节 | 簇 | 配图描述 | 状态 | 你要做的 |
|---|---|---|---|---|
| 02 | 2 | 结算阶段倒计时 | 占位 | 给 Figma 这张图 / 给我图我补 |
| 03 | 1 | 头像列对比 | 未找到源 | 补 assetMap 或删掉这条 |
```

- 状态取值：`已配` / `占位` / `未找到源` / `填充失败`
- 有缺图时，成功报告末尾固定加一句："还有 N 张配图没贴，别忘了手动配图（或把图发我，我用同步模式补）"
- 审计结论不影响交付判定：用户说"先这样"，直接进 Phase 5

替代方案：只读引擎统计不截图——被否决，用户要的是"截图检查"；统计看不到占位被误填的情况。

### D4 · 审计范围按章节截，不整页截

整页截图在长文档上会被 Figma 缩放压扁，看不清灰板；按章节截能对上"一节一图"的心智模型，也便于把缺图定位到具体簇。章节数 > 8 时允许分批，先截前 8 章并把剩余列成"待核对"。

### D5 · 版本与文案同步面

- `packages/skill/package.json` / `manifest.json` / 根 `package.json` version → `2.3.0`；`engineVersion` 不变
- `SKILL.md`：description 里"用户给一份策划文档…"改为"用户给设计稿 / Figma 链接 / 策划文档…"；Phase 1 行、Phase 切换规则表 Phase 1 行、Phase 3 行、Phase 4 行、输出契约表同步
- `phase1-analysis.md`：新增「开场材料引导（设计稿优先）」段，改造入场材料识别段落开头
- `phase2-markdown.md`：默认配图规则 + 自检清单条目
- `phase3-asset.md`：说明配图条目来源已由 Phase 2 保证，Phase 3 不再询问"要不要配图"
- `phase4-figma.md`：新增「配图审计」小节，结果 A / 结果 D 模板各加审计行
- `CHANGELOG.md`：`v2.3.0` 条目

## Risks / Trade-offs

- [每簇强制配图会让小界面产出过多配图] → 允许"本簇无配图 + 理由"，且 W3 已限"一态一图"，配合 Phase 2 自检控制数量
- [截图审计拉长 Phase 4 收尾] → 按章截、章节多时分批；审计只读不写画布
- [截图看不出占位（低分辨率/缩放）] → 引擎统计为准，截图只做补充发现；两者矛盾时以统计 + 单点 `figma_execute` 复核
- [开场改问设计稿，用户手上只有文档会觉得被打断] → 话术里第一句就给出"还没有 → 发策划文档"的分支，不产生额外回合

## Migration Plan

纯文档变更，无数据迁移。已安装 skill 的用户需重跑 `scripts/install-skill.mjs`（或重新下载）才拿到新流程；老会话不受影响。
