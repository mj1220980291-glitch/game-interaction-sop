# Phase 1 — 需求挖掘

## 进入条件

用户给出策划文档/截图/口头需求。

## 完成条件

`已确认`列表足以支撑写出 v2 Markdown（即所有 ` ## NN.` 的界面名称、每个界面内的语义簇及其规则都明确）。

---

## 第一回合标准结构

```markdown
我当前理解：
- ...

这个需求初步属于：[类型]。

我先确认 1-3 个会影响交互文档落地的问题：
1. ...
2. ...
3. ...
```

**禁止在第一回合输出**：风险点、验收点、完整交互文档、示意图清单、实施计划、OpenSpec proposal/tasks/spec。

跳过提问的唯一例外：用户显式说"不要提问 / 直接输出 / 不用追问"，或会话已经包含全部关键决策的答案。跳过时必须说明为什么跳过。

---

## 后续回合标准结构

```markdown
已确认：
- ...
- ...

我还需要确认：
1. ...
2. ...
3. ...
```

每轮 ≤ 3 个问题，最关键的一个就够。用户答完，先把答案变成`已确认`再问下一轮。

---

## 提问的判断标准

**应当问**：会改变以下任何一项的问题——

- 触发条件
- 目标对象/命中区域
- 输入方式（点击/hover/快捷键/拖拽/长按/平台手势）
- 可见 UI 状态
- 成功/失败反馈
- 动效/音效序列
- 资源/数据/配表规则
- 边界情况
- 平台差异
- 下游交付物

**不应当问**：低影响视觉偏好、字号、颜色（除非影响可读性/遮挡/适配）。

---

## 需求分类（用于挑相关问题，不暴露给用户）

- **资源操作**：货币、能量、道具、堆叠、消耗、获得、不足态、批量
- **目标选择**：单位、卡牌、目标、网格、模型、铭牌、命中区重叠
- **拖拽与释放**：起拽、有效区、无效区、释放、取消、归位
- **阶段提示**：回合、倒计时、过渡、预告、强制显示、可中断
- **列表/商店**：刷新、购买、锁定、排序、空态、推荐、重复提示
- **弹窗/展示**：阻断、排序、入/闲/出场序列、可跳过、N 项处理
- **进度/计数**：堆叠数、量表、阈值、最大、溢出、聚合
- **设置选项**：开关、持久化、默认值、作用域、跨平台
- **奖励/结算**：结果、胜负、补偿、动画、领取
- **混合/不明**：先问一个分类问题再继续

## 完成度评估

- **信息不足**：核心触发/对象/目标不清。继续问。
- **信息可用**：可以写出 v2 Markdown 第一版（容许少量`待补充`）。可以进入 Phase 2。
- **信息充分**：v2 Markdown 可以定稿无遗留。

不要追求完美确定。够用就推进。

---

## 反污染

- 不让过往任务（卡牌/资源/战斗等）变成本需求的默认假设
- 不预设需求是某种类型，除非输入支持
- 用通用交互原语起步：目标/场景/触发/对象/输入/状态/反馈/边界/下游/交付物
- 分类不确定时先问一个分类问题再深入

## Phase 1 结束的明确信号

LLM 主动告诉用户：

> "需求已经收敛得够写一份 v2 Markdown 了。我现在进入 Phase 2，先把完整 Markdown 输出来给你审，你确认后我保存到磁盘。"

然后切换到 `phase2-markdown.md`。
