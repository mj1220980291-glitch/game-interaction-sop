# Phase 5 — 文风沉淀（Style Learn）

## 定位

Phase 4 完成后统一收口：把这一轮被人工改过的**表述**沉进本次生效的文风文件（默认 `style_own.md`）。

两个入口：

| 入口 | 素材 | 谁改的 |
|---|---|---|
| A. Markdown | 本轮交互文档 md 的改动点 | 用户在 md 审核/事后修改 |
| B. Figma | 已写入的 Figma 文档里的表述改动 | 用户在 Figma 里二次修改 |

原 Phase 2 / Phase 4 的两处回写闸门合并到这里，**只问一次**，不在中途重复刷存在感。

---

## 进入 / 完成条件

- **进入**：Phase 4 完成（用户在 Figma 看到结果，或显式跳过写 Figma）
- **完成**：两个入口都问过 → 用户确认或拒绝 → 需写入的已写入 → 快照已刷新 → 报一行摘要

用户显式说“这次不用沉淀 / 别问了” → 本次跳过，直接进 Phase 6。

---

## 快照机制

- Phase 2 保存 Markdown 后**立即**存一份原稿到 `<项目根>/.interaction-sop/snapshots/<需求名>.md`
- Phase 5 用「快照 vs 现行 md」做 diff，diff 出来的就是本轮人工改动
- Phase 5 结束把快照覆盖为当前 md，避免下一轮重复沉淀同一条
- 快照缺失（老文档、用户换了路径）→ 直接问用户要改后的文件/路径；拿不到就跳过入口 A，只走入口 B

> 快照只是个 diff 基线，不是版本库。同名文件覆盖，不保留历史。

---

## Step 1 — Markdown 改动 → style 条目

1. diff 快照与现行 md，逐处列出改动（用局部 diff，不要把整篇重读一遍）
2. **只收表述层**：措辞、句式、`@职能` 标注方式、动效句写法、红点四要素、bullet 粒度、段内顺序
3. **不收业务内容**：具体数值、某界面专属规则、增删章节、配图替换
4. 归成 style 条目，一条一句话，写明落到哪里、依据是什么：

```
条目：渐隐统一写成渐出
落点：wording.replace
依据：你把 3 处「渐隐」改成了「渐出」
```

5. **一次列清单确认**，不逐条追问：

```
本次从 md 改动里提炼出 N 条表达习惯：

1. 「渐隐」统一写成「渐出」 → wording.replace ← 你把 3 处渐隐改成渐出
2. 动效一律单独成条 → 正文段·动效写法 ← 你把 #4 的动效句拆了出来
3. ...

要保留哪几条？（回编号 / 「全部保留」/「都不要」）
```

6. 用户挑完 → 进 Step 3

---

## Step 2 — Figma 表述改动（主动问一句）

固定话术：

```
另外，如果你在 Figma 文档里改过表述（不只是挪气泡），把最新文档链接/node 给我，
我读回来自己总结你的表达习惯，一起存进 style_own。
```

- 用户给链接 → 用只读工具读文本（`figma_get_file_for_plugin`；实例内文本取不到时用 `figma_get_file_data` + `verbosity: full` + 足够 `depth`）
- 与快照 / 现行 md 逐条比，只取表述层差异，归成条目
- 与 Step 1 的清单**合并成一张表**，加一列「来源：md / Figma」，一次确认
- 用户说没改过 / 不想沉淀 → 本会话不再提第二次
- **Figma 专属不算文风**：排版、气泡位置、配图更换、图层结构

---

## Step 3 — 写入本次生效的文风文件

先看本次文档用的是哪份（Phase 1 的「文件选择顺序」结论），再定写入目标：

| 本次启用 | 沉淀写哪 |
|---|---|
| `style_own.md` | `style_own.md` |
| `style_<name>.md` | 写回该份（你选了谁的文风，本轮改动就归谁） |
| `style.md`（首次，还没有 own） | **不写 `style.md`**：以它为基底复制出 `style_own.md`，再追加条目 |
| 一个文风文件都没有 | 按 `references/style-mod-schema.md` 骨架新建 `style_own.md`（`schema_version: 1`），只填确认过的条目 |

写入规则：

1. 写前备份 `<目标文件>.bak`
2. **只改涉及字段与正文段**，不重排、不删用户手写段落
3. `style.md` 任何情况下不写入，保持干净基线
4. 冲突处理：
   - 与不可覆盖项（H\* / C2 / T10 / T2）冲突 → 拒收，并说明为什么不能收
   - 与现有 `banned` 冲突（要保留的写法本身就是禁用词）→ 先问再改
   - 同一字段已有同义条目 → 合并，不叠重复项
5. 写完报一行：`<目标文件> 已更新：N 条（字段 X 条 / 正文段 Y 条）`

---

## Step 4 — 收尾

- 快照覆盖为当前 md
- 一句话交付 + 进 Phase 6：

```
本轮沉淀 N 条（md 入口 X 条 / Figma 入口 Y 条），未保留 M 条。
接着看要不要维护模式库。
```

---

## 不该做的

- 不在 Phase 2 审核中途、Phase 4 写完当下重复问沉淀 —— 统一到 Phase 5
- 一次最多提 5 条；超过就只留出现频次最高的
- 不为了一处改动重写整份 style
- 不把业务规则、数值、界面专属逻辑写进 style
- 不把 Figma 排版类改动当表述习惯
