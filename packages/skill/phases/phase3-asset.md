# Phase 3 — 索要设计稿

## 进入条件

Phase 2 完成（v2 Markdown 已保存到磁盘）。

## 完成条件

用户给出三种之一：
1. 一张/多张设计稿图片（粘贴到对话或本地路径）
2. Figma 链接（指向具体 node）
3. 显式说"跳过"

---

## 标准索要话术

```
Markdown 已保存。下一步我要把它写入 Figma。

为了让每个气泡贴在主图的正确位置，我需要这个需求对应的高保真设计稿：

1. 直接发图片（拖入对话或贴本地路径）
2. 发 Figma 链接（指向具体 node 即可，例如 .../design/...?node-id=xxxx）
3. 暂时没有 → 输入"跳过"，我会用主图占位符代替；等你后续补图时再回填位置

每个 ## NN. 章节对应一张主图。如果不同界面用不同图，请按章节顺序分别提供；如果都用同一张，告诉我"都用同一张"即可。
```

---

## 用户响应处理

### 响应 1：发了图片

- 记录图片路径/data
- 询问：这张图对应哪个/哪些 `## NN.` 章节？
- 多张图时，按用户给的对应关系记录

### 响应 2：发了 Figma 链接

- 解析出 `fileKey` 和 `node-id`
- 询问：这个 node 对应哪个/哪些 `## NN.` 章节？

### 响应 3：跳过

- 记录所有章节的 `主图 = 占位符`
- 告诉用户：Phase 4 会用占位符 `主图占位：待手动替换`，气泡按默认网格排（用户后续可手动调位）

### 响应 4：部分提供（推荐处理路径）

允许用户只给部分章节的图。未提供的章节走"占位符 + 默认网格"。

---

## Phase 3 内部数据结构（传给 Phase 4）

整理为：

```
{
  "asset_map": {
    "01": { "type": "image", "src": "..." },
    "02": { "type": "figma_node", "fileKey": "...", "nodeId": "..." },
    "03": { "type": "skip" }
  }
}
```

---

## Phase 3 结束的明确信号

向用户复述确认：

```
设计稿确认：
- 第 01 章「界面名称X」→ [图片/Figma链接/跳过]
- 第 02 章「界面名称Y」→ [图片/Figma链接/跳过]
- 第 03 章「XX全局展示」→ 全局规范章节，引擎自动跳过主图
- ...

确认无误后我开始 Phase 4：写入 Figma。
```

用户确认后切换到 `phase4-figma.md`。

---

## 严禁

- ❌ 不问用户、自己决定全部用占位符
- ❌ 不问用户、自己决定全部章节共用一张图
- ❌ 用户说跳过却仍然反复追问
- ❌ 对用户提供的 Figma 节点走 `reparent` 路径贴图（会触发 pitfalls.md 陷阱 1 坐标爆炸；必须走 `rasterizeNodeToImageFill`）
- ❌ 给全局规范章节索要主图（应直接识别关键词并跳过）
