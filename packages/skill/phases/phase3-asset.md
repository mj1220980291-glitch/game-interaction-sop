# Phase 3 — 索要设计稿

## 进入条件

Phase 2 完成（v2 Markdown 已保存到磁盘）。

## 完成条件

用户给出三种之一：
1. 一张/多张设计稿图片（粘贴到对话或本地路径）
2. Figma 链接（指向具体 node）
3. 显式说"跳过"

> **路径A 退化模式**：本次需求若走路径A（入场时图已在手，见 `phase1-analysis.md` 入场材料识别），Phase 3 退化为**资产确认**而非"索要设计稿"——见下方专门段落。Phase 3 的编号与门禁位置不变（Phase 4 之前仍需资产确认或显式跳过）。

---

## 路径A 退化模式（图已在手）

入场时已提供草稿 / 截图 / 设计稿，且这些图已在 Phase 2 Step 0.1 作为章节锚定时，Phase 3 **不再执行完整"索要设计稿"话术**，只需确认：

```
你入场时已提供了 N 张图，Phase 2 章节也是按它们切的。写入 Figma 前确认：

1. 这些图能直接作为各章节主图吗？（清晰度够 / 是成品态）
   - 能 → 我按 章节↔图 的对应关系直接用
   - 不够清晰或是草稿 → 发我对应章节的高清版 / Figma node
2. 有没有哪个章节需要补充局部图（卡片内部、icon、悬浮层细节）？
3. 全局规范章节（命中 全局/规范/组件/汇总）自动跳过主图，无需提供

确认后进入 Phase 4。
```

- 入场图可直接用 → `asset_map` 对应章节填 `image` / `figma_node`
- 入场图是低保真草稿、需替换为高清成品 → 按用户补的图回填，未补的章节走占位符
- 用户说"草稿就行/先占位" → 走"跳过"，Phase 4 用占位符

## 标准索要话术（路径B / 入场无可用图）

```
Markdown 已保存。下一步我要把它写入 Figma。

为了让每个气泡贴在主图的正确位置，我需要这个需求对应的高保真设计稿：

1. 直接发图片（拖入对话或贴本地路径）
2. 发 Figma 链接（指向具体 node 即可，例如 .../design/...?node-id=xxxx）
3. 暂时没有 → 输入"跳过"，我会用主图占位符代替；等你后续补图时再回填位置

每个 ## NN. 章节对应一张主图。如果不同界面用不同图，请按章节顺序分别提供；如果都用同一张，告诉我"都用同一张"即可。
```

## 用户响应处理

### 响应 1：发了图片

- 记录图片路径/data
- 询问：这张图对应哪个/哪些 `## NN.` 章节？
- 多张图时，按用户给的对应关系记录

### 响应 2：发了 Figma 链接

- 解析出 `fileKey` 和 `node-id`
- 询问：这个 node 对应哪个/哪些 `## NN.` 章节？

### 响应 3：跳过

- 记录所有章节的 `主图 = 占位符`
- 告诉用户：Phase 4 会用占位符 `主图占位：待手动替换`，气泡按默认网格排（用户后续可手动调位）

### 响应 4：部分提供（推荐处理路径）

允许用户只给部分章节的图。未提供的章节走"占位符 + 默认网格"。

## 配图资产（主图确认之后）

Markdown 含 `配图：` bullet、且用户给了 Figma 设计稿时，主图确认完再做这一步。用户说"配图先不贴"则整步跳过。

### 1. 编键

每条 `配图：` 一个键 `"NN/C/K"`：第 NN 章、第 C 个 `###` 簇（1 起）、该簇内第 K 张配图（1 起）。**K 按簇内全部 `配图：` 的文档顺序数，跨 `####` 连续，不重置。**

### 2. 定位源区域

按 `配图：` 描述，在设计稿里找：

- `nodeId`：源节点（通常是设计稿里对应状态的那张 1920×1080 画板）
- `crop`：要截的区域，**相对该节点左上角**，`{ x, y, width, height }`；整张都要就省略

源节点必须在**渲染目标文件**内（引擎插件只能访问当前文件）。不在的，告诉用户：先把源画板复制到目标文件，或跳过这张。

找不到对应画面的配图**不写键**，不猜区域。

### 3. 截图清单给用户确认

对每个区域用 `figma_capture_screenshot`（或 `figma_execute` 导出该区域）截图，连同清单发给用户：

```
配图资产（共 N 张，待确认）：
- 01/1/1 「阶段名与倒计时位置」 ← 设计稿「搜捕阶段」(588:6399) x=700 y=0 w=520 h=160  [截图]
- 01/1/2 「结算阶段的居中倒计时」 ← 设计稿「结算」(588:5130) x=760 y=0 w=400 h=180  [截图]
- 01/2/1 「普通模式与感染模式的头像列对比」 ← 未找到源，保留占位

确认 / 指出要改的区域。
```

用户确认后写入 `asset_map`；用户否决的那张删掉键。

### 4. 尺寸规则（告知即可，无需用户决定）

引擎按 `crop` 的宽高比给配图框定高：宽 = min(区域宽, 说明栏宽 1231)，高按比例；小图不放大。所以 **`crop` 框多大，文档里就多大**——截得太松会留大片空白，截得太紧会切到内容。

## Phase 3 内部数据结构（传给 Phase 4）

整理为：

```
{
  "asset_map": {
    "01": { "type": "image", "src": "..." },
    "02": { "type": "figma_node", "fileKey": "...", "nodeId": "..." },
    "03": { "type": "skip" },
    "01/1/1": { "type": "figma_node", "fileKey": "...", "nodeId": "588:6399",
                "crop": { "x": 700, "y": 0, "width": 520, "height": 160 } },
    "01/1/2": { "type": "figma_node", "fileKey": "...", "nodeId": "588:5130",
                "crop": { "x": 760, "y": 0, "width": 400, "height": 180 } }
  }
}
```

- `"NN"`：章节主图（可选 `crop`，主图占位尺寸不变）
- `"NN/C/K"`：配图，只支持 `figma_node` / `skip`

## Phase 3 结束的明确信号

向用户复述确认：

```
设计稿确认：
- 第 01 章「界面名称X」→ [图片/Figma链接/跳过]
- 第 02 章「界面名称Y」→ [图片/Figma链接/跳过]
- 第 03 章「XX全局展示」→ 全局规范章节，引擎自动跳过主图
- ...
- 配图资产：已确认 N 张 / 保留占位 M 张（或：配图先不贴）

确认无误后我开始 Phase 4：写入 Figma。
```

用户确认后切换到 `phase4-figma.md`。

## 严禁

- ❌ 不问用户、自己决定全部用占位符
- ❌ 不问用户、自己决定全部章节共用一张图
- ❌ 用户说跳过却仍然反复追问
- ❌ 对用户提供的 Figma 节点走 `reparent` 路径贴图（会触发 pitfalls.md 陷阱 1 坐标爆炸；必须走 `rasterizeNodeToImageFill`）
- ❌ 给全局规范章节索要主图（应直接识别关键词并跳过）
- ❌ 没经用户确认就把 AI 定位的配图区域写进 `asset_map`
- ❌ 找不到源画面时猜一个区域填上（应不写键、保留占位）
