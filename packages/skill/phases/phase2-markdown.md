# Phase 2 — v2 Markdown 生成

## 进入条件

Phase 1 已达到`信息可用`或`信息充分`。

## 完成条件

- 完整 v2 Markdown 已在对话中输出，用户确认无误
- Markdown 通过 `references/markdown-v2-spec.md` 全部强校验
- 文件已保存到磁盘

---

## 第一步：在对话里输出完整 Markdown

直接按 `references/markdown-v2-spec.md` 的模板写出完整 Markdown，**不省略任何章节**。

输出前自检（按强校验逐项过）：

- [ ] 文件头 4 行齐全（跟进UI / 需求组 / 易协作链接 / 最后更新时间）
- [ ] 一级标题只有 `# [需求名称]` 一个
- [ ] `## 设计总览` 唯一存在
- [ ] 设计总览下正好 `### 功能背景` + `### 核心交互` 两块，无其他三级标题
- [ ] 至少 1 个 `## NN. [界面名称]`
- [ ] `##` 序号连续：`01, 02, 03, ...`
- [ ] 每个 `## NN.` 至少 1 个 `###`
- [ ] 设计总览以外的每个 `###` 下方第一行是 `@角色...`
- [ ] 角色名单只用：`@程序 @GUI @拼接 @美术 @动效 @音频 @策划`（详见 `../references/role-tags.md`）
- [ ] `###` 命名是该功能/组件的名字（如"经验条"/"一键领取按钮"），不是规则属性（如"显示规则"/"动效表现"/"异常与边界"）
- [ ] 每个 `###` 数量符合"主图上能独立指气泡的看得见的东西"数量，等于策划文档原标号数
- [ ] 同一功能涉及的所有规则（显示/状态/动效/异常/网络）都聚集在该功能的 ### 内，不被拆到多个 ###
- [ ] 【C3 硬规则】一个视觉单元的所有状态/hover/态切换规则必须聚在同一个 `###`，禁止拆成"默认态 ###" + "hover态 ###"
- [ ] bullet 原子化（一条规则 = 一个条件 + 一个行为 + 一个结果）
- [ ] 【可选】一个 `###` 下 bullets ≥ 6 条且能分类时，考虑用 `#### 子分类标题` 做内部分组（例如"基础信息" / "升级反馈"），详见 `markdown-v2-spec.md` 的"簇内子分类小标题"章节

---

## 第二步：请用户审核

在 Markdown 后面附上简短的请求：

```
请审核上面这份 Markdown：
- 字段是否准确？
- 章节切分是否合理？
- 任何一条规则需要修改/补充？

确认无误后我保存到磁盘。
```

如果用户提修改，按修改重写完整 Markdown，再次请求确认。**不要发"差异 patch"，每次都重发完整版**——便于用户复制到自己的工具。

---

## 第三步：确认默认保存路径

第一次进入 Phase 2 时，问一次保存路径：

```
确认保存路径：
[默认] H:\...\[策划文档同目录]\[需求名]_交互文档.md
[或] 其他路径
```

如果策划文档路径已知（用户在 Phase 1 给出的路径），用同目录 + `[需求名]_交互文档.md` 命名。

---

## 第四步：保存

调用文件写入工具把 Markdown 写到磁盘。写完告诉用户：

```
✅ 已保存：[完整路径]
```

LLM 主动告诉用户：

然后切换到 `phase3-asset.md`。

## 章节内 ### 拆分启发法（写 Markdown 时用）

对每个 `## NN. [界面名称]`：

1. 把该界面相关的所有规则/决策列出来
2. 按"哪些下游角色需要一起读懂这一组规则才能干活"分组
3. 每组 = 1 个 `###`，名字用语义动词短语描述这组规则在解决什么（例如"入口规则" / "选中与hover区分" / "显示位置与层级" / "关闭与刷新" / "养成与解锁展示" / "技能详情说明" / "属性详情" / "出售规则" / "成功反馈"）
4. `###` 下方写 `@角色1 @角色2 ...`，列出该组规则真正涉及的角色
5. 组内规则按 bullet 列出
6. 仅当确实需要局部图（状态对比 / 动效分镜等）时，在该组最后加一条 `- 配图：xxx`

`### ≥ 1`，无上限。0 个意味着该界面无意义。

---

## 严禁

- ❌ 出 v0 / v1 旧格式（`### 功能定位 / 显示规则 / 操作规则 / 反馈表现 / 异常与边界 / 配图说明`）
- ❌ 全局 `## 主图标注` 表
- ❌ 全局连号气泡
- ❌ 文件头加 `平台优先级` / `适用下游` / `Figma交互文档` / `高保真设计稿`
- ❌ 默认输出 `### 待确认` 或 `## 待确认问题汇总`
- ❌ Markdown 写完不让用户审就直接 Phase 3
