## 簇结构约定

- 簇名下第一行 `@角色...` 列出所有相关职能
- 簇正文 5–10 条 bullet，结构固定：
  - 第 1 条：功能一句话简述（这是什么、玩家在哪遇到）
  - 其后：**每个相关职能一条 `- @职能：…`**，各自写自己要关注的开发信息
- 不写"全职能通用"的长描述，细节分散到各职能条目里

## 职能标注

- `@角色` 行列出所有相关职能后，正文按职能逐条铺开
- 每条 `- @职能：` 自包含，不写"同上 / 见上"，不重复角色名
- 命中但无增量信息的职能可省略单条
- 两职能协作（"策划配、程序判"）拆成两条，各写自己负责的部分

### 顶部 @角色 行必须覆盖簇内所有职能（硬规则）

- 簇名下第一行 `@角色...` 必须列出该簇正文出现的所有 `- @职能：` 条目对应的职能
- 不得出现下方 `- @动效：…` 而顶部漏写 `@动效` 的情况
- 写完一簇做一次扫描：顶部角色集合 ⊇ 正文出现的职能集合

### 同簇内同一职能多条合并（硬规则）

- 同一簇内有 ≥ 2 条属于同一职能的 bullet 时，必须合并成一条
- 格式：`- @职能：` 作为头，换行后 2 空格缩进 `1.`/`2.`/`3.`/`4.` 编号列表
- 示例：
  ```markdown
  - @程序：
    1. Delay 数值由客户端 ping 服务端得出，Personnel 列显示 当前人数/人数上限
    2. 点击任意行选中该房间，右侧详情面板同步切换
    3. 刷新后原选中房间仍存在则保留选中，房间已消失则回到右侧空态
  ```
- 单条职能条目仍写一行 `- @职能：…`，不强行加编号

## 配图占位（硬规则）

当簇中出现任一「资源状态说明」时，必须紧跟一条 `- 配图：xxx` 占位 bullet，供设计师后续补图：

- 判定命中「资源状态说明」的任一特征：
  1. `- @GUI：需要新出 … 态 / 状态外观 / 空态图 / 角标` 等新资源描述
  2. 一个控件描述里出现 ≥ 2 种外观形态（如"默认/置灰"、"空态/内容态"、"收起/展开"）
  3. 显式状态行：`xx状态：…`、`xx态：…`
- 占位 bullet 位置：**紧跟触发该判定的那条规则下方**，不集中堆到簇末
- 占位 bullet 格式：`- 配图：补<具体状态描述>图`
  - 例：`- 配图：补刷新图标与冷却置灰态`、`- 配图：补搜索框默认/输入/无结果三态`
- 一个簇需要几种状态图，就补几条占位 bullet；多种状态可写在同一条，用「、」连列
- 不含资源状态变化的纯逻辑簇（如"打开弹窗"）不加占位

## 结构偏好

- 簇名（`###`）名词化：控件 / 信息块名词（`队伍排行栏`、`基础信息`），不写「xx规则 / xx说明」这类规则属性名
- 不用 `####` 分段（`structure.layout: flat`），全部 bullet 平铺在簇内
- `- 配图：…` 紧跟触发它的那条规则下方，不堆到簇末
- `- @动效：…` 一律独立成条并落在簇末，不写无前缀的动效句
- `- @职能：…` 紧挨它说明的规则，不集中堆到簇末；与规则无关的通用流程不标职能

## 示例

好：

```markdown
### 进入房间按钮
@程序 @GUI @动效

- 位于详情面板底部，点击进入当前选中房间的 3D 场景
- @程序：已满或游戏中置灰不可点，点击无响应且不弹提示
- @程序：密码房可点，点击后先弹密码输入，校验失败提示「密码错误」并留在弹窗内
- @GUI：需新出默认态、悬停态、按下态、置灰态
- 配图：补置灰态、补密码校验弹窗
- @动效：点击后按钮按压回弹，进入场景时面板整体淡出
```

坏：

```markdown
### 进入房间按钮相关规则
@程序 @GUI

- 点按钮进房间，满员和游戏中置灰，密码房要先输密码，失败提示密码错误，按钮有默认悬停按下三种状态，点击有按压动效（一长条混装：程序规则、GUI 资源、动效全挤在一句）
```
