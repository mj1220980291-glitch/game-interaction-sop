# v2 Markdown 格式规范（权威契约）

本文件是 game-interaction-sop 各 Phase 与下游 figma-interaction-doc-engine 的**唯一格式契约**。Markdown 文档只要通过本规范的强校验，就保证可被引擎确定性地写入 Figma 模板 1:14。

---

## 模板（复制即用）

```markdown
# [需求名称]

跟进UI：[姓名]
需求组：[组名]
易协作链接：[链接或 #待补充]
最后更新时间：YYYY.MM.DD

## 设计总览

### 功能背景

[一段说明文字。讲清楚：本功能解决什么问题、玩家在哪里看到、为什么需要它。]

### 核心交互

[一段说明文字。讲清楚：本功能的核心交互结论、关键规则总结。]

## 01. [界面名称]

### [自由命名的语义簇 1]
@程序 @GUI

- 规则 1
- 规则 2
- 配图：[局部截图/状态对比图，待补充]   ← 可选，只在该簇真有局部图时加

### [自由命名的语义簇 2]
@动效 @音频

- 规则 1
- 规则 2

## 02. [界面名称]

[同样结构，章节内 ### 序号重新从 1 开始，不全局连号]

## NN. [界面名称]

[同样结构]
```

## 强校验（不通过 → 引擎拒绝写 Figma）

| ID | 规则 | 说明 |
|---|---|---|
| H1 | 文件头 4 行齐全 | `跟进UI` / `需求组` / `易协作链接` / `最后更新时间`，顺序固定，缺一不可 |
| H2 | 第一行是 `# [需求名称]` | 一级标题只有这一个 |
| O1 | `## 设计总览` 存在且唯一 | |
| O2 | 设计总览下必须正好包含 `### 功能背景` + `### 核心交互` 两块 | 顺序固定，缺一不可，禁止其他三级标题 |
| S1 | 至少有一个 `## NN. [界面名称]` 章节 | NN 从 01 开始，零填充两位 |
| S2 | `##` 章节序号必须连续：`01, 02, 03, ...` | 不准跳号 |
| C1 | 每个 `## NN.` 下至少 1 个 `###`（无上限） | 0 个等于该界面无意义 |
| C2 | 设计总览以外的每个 `###` 下方第一行必须是 `@角色1 @角色2 ...` | 空格分隔，至少 1 个角色 |
| G1 | `####` 子分类标题只能出现在 `###` 内部 | `#### ` 出现在 `## NN.` 直属内容区（`###` 之前）→ `H_H4_ORPHAN` |
| G2 | `####` 标题长度 ≤ 24 显示宽度（中文字 ≤ 12 个） | 超长 → `H_GROUP_TITLE_LEN_OVERFLOW` |
| G3 | 同一 `###` 簇内 `####` 标题不可重复 | 大小写不敏感 → `H_GROUP_TITLE_DUPLICATE` |

## 软约束（违反 → 引擎给出提醒，不阻断）

| ID | 规则 | 说明 |
|---|---|---|
| W1 | `@角色` 必须从 7 个角色名单里选 | 见 `role-tags.md` |
| W2 | `###` 命名用语义动词短语 | 例："入口规则"/"选中与hover区分"/"关闭与刷新"。**禁止**："显示规则"/"操作规则"/"反馈表现"/"异常与边界" 这类死分类 |
| W3 | `- 配图：xxx` 只在该语义簇确实需要局部图时加 | 作为该 `###` 内的最后一条 bullet |
| W4 | bullet 保持原子性：一条规则 = 一个条件 + 一个行为 + 一个结果 | 长复合规则拆多条 |
| W5 | `####` 之前有游离 bullet → 建议全分组或全不分 | 混用时 parser emit `W3_CLUSTER_MIXED_FREE_BULLETS_AND_GROUPS`，不阻塞 |

## 簇内子分类小标题（`####`，可选）

当一个 `### 语义簇` 的 bullets 较多（建议 ≥ 6 条时考虑）且能分类时，可以在簇内用 `####` 把 bullets 切成若干组：

```markdown
### 经验条
@程序 @GUI @动效

#### 基础信息
- 当前等级标签右侧显示一条黄色进度条
- 展示玩家当前等级的经验进度

#### 升级反馈
- 经验条满格时触发升级特效（爆发光效）
- 当局连升多级时，升级特效循环播放
- 满级时经验条显示为满格静止状态
```

**规则**：

- `####` 是**软约束**，不要求所有簇都分组，视内容粒度决定
- 一个簇可以有 0、1 或多个 `####`
- 分组名长度 ≤ 12 个中文字（显示宽度 ≤ 24）
- 同一簇内 `####` 标题不可重复
- `####` 必须出现在 `### 语义簇` 内部，**不能**在 `## NN.` 直属范围（没有 `###` 时直接写 `####` → 硬错误）
- 建议要么全分组、要么全不分，避免"游离 bullets + ####"混用（会产生软警告）

## 章节内气泡编号规则（关键）

- 每个 `## NN. [界面名称]` 自带一张主图（全局规范章节例外）
- 该章节内 `###` 的序号（1, 2, 3, ...）= 该图上对应气泡的编号
- **章节内连号，不全局连号**
- 例：`## 01.` 内有 5 个 `###` → 该图上有气泡 1、2、3、4、5；`## 02.` 内有 8 个 `###` → 该图上有气泡 1、2、3、4、5、6、7、8（重新从 1 开始）

---

## 全局规范章节（自动识别）

章节名命中关键词 **`全局 / 规范 / 组件 / 汇总`** 的 `## NN.`，被引擎识别为"全局规范章节"。例：

- `## 03. 等级数字全局展示`
- `## 04. 按钮组件规范汇总`

对这类章节，引擎行为：

- ❌ 不索要主图（Phase 3 自动跳过该章节）
- ❌ 不在模板上保留主图占位 / 占位文案
- ❌ 不布气泡（`气泡` FRAME 被整体删除）
- ✅ 右栏 `说明块` 正常渲染 `### 语义簇`

如果一个章节确实要展示一组组件而不关联一张具体界面图，用这些关键词命名即可；否则请补一张主图（哪怕是多图拼贴的汇总图）。

## 不要做的事（v2 明确移除的格式）

- ❌ 全局 `## 主图标注` 表格
- ❌ 文件头 `平台优先级` / `适用下游` / `Figma交互文档链接` / `高保真设计稿链接`
- ❌ 固定 6 槽位 `### 功能定位 / 显示规则 / 操作规则 / 反馈表现 / 异常与边界 / 配图说明`
- ❌ 独立 `### 配图说明` 槽位（已合并为某簇最后一条 bullet）
- ❌ 独立 `### 注意事项` 槽位
- ❌ 独立 `### 待确认` 槽位 / `## 待确认问题汇总` 段（默认不输出）
- ❌ 全局连号气泡

## 与 Figma 模板字段映射（速查）

详见 `template-1-14.md`。最常用的：

| Markdown | 模板节点 |
|---|---|
| `# [需求名称]` | 文档标题 (1:31) |
| 文件头 4 行 | 标题组件下 4 个 TEXT (1:29 / 1:27 / 1:28 / 1:26) |
| `### 功能背景` 段 | 功能背景 frame (1:36) |
| `### 核心交互` 段 | 核心交互 frame (1:39) |
| 每个 `## NN.` | 克隆"界面说明 N"组 (基于 1:44) |
| 每个 `###` | 该界面说明右侧"小标题"块（含气泡编号、小标题、@角色行、说明段、可选配图占位） |
