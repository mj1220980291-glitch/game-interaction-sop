# v2 Markdown 格式规范（权威契约）

本文件是 game-interaction-sop 各 Phase 与下游 figma-interaction-doc-engine 的**唯一格式契约**。Markdown 文档只要通过本规范的强校验，就保证可被引擎确定性地写入 Figma 模板 1:14。

---

## 模板（复制即用）

```markdown
# [需求名称]

跟进UI：[姓名]
需求组：[组名]
易协作链接：[链接或 #待补充]
最后更新时间：YYYY.MM.DD

## 设计总览

### 功能背景

[一段说明文字。讲清楚：本功能解决什么问题、玩家在哪里看到、为什么需要它。]

### 核心交互

[一段说明文字。讲清楚：本功能的核心交互结论、关键规则总结。]

## 01. [界面名称]

### [自由命名的语义簇 1]
@程序 @GUI

- [是什么：作用 / 何时出现 / 数据来源]
- [怎么交互：操作 → 直接结果]
- 配图：[交互的局部截图]   ← 可选，紧跟它说明的那条规则
- [名字]状态：[出现条件]   ← 状态行；简单状态只写"[名字]状态"
- 配图：[该状态的截图]     ← 一簇可多张
- [反馈：toast / 音效 / 特效]
- [什么情况下]，[需要什么样的动效]   ← 动效句，无前缀；放在簇末

### [自由命名的语义簇 2]
@动效 @音频

- 规则 1
- 规则 2

## 02. [界面名称]

[同样结构，章节内 ### 序号重新从 1 开始，不全局连号]

## NN. [界面名称]

[同样结构]
```

## 强校验（不通过 → 引擎拒绝写 Figma）

| ID | 规则 | 说明 |
|---|---|---|
| H1 | 文件头 4 行齐全 | `跟进UI` / `需求组` / `易协作链接` / `最后更新时间`，顺序固定，缺一不可 |
| H2 | 第一行是 `# [需求名称]` | 一级标题只有这一个 |
| O1 | `## 设计总览` 存在且唯一 | |
| O2 | 设计总览下必须正好包含 `### 功能背景` + `### 核心交互` 两块 | 顺序固定，缺一不可，禁止其他三级标题 |
| S1 | 至少有一个 `## NN. [界面名称]` 章节 | NN 从 01 开始，零填充两位 |
| S2 | `##` 章节序号必须连续：`01, 02, 03, ...` | 不准跳号 |
| **S3** | **`## NN.` 章节名必须含界面关键词清单 OR 命中全局规范白名单** | 界面关键词：`界面 / 面板 / 页 / 窗 / 卡 / 弹窗 / 弹层 / 区 / 条 / 栏 / 区域 / 版 / 入口 / 反馈 / 场景`；全局规范白名单：`全局 / 规范 / 组件 / 汇总 / 流程 / 结算`。否则 `H_SECTION_NOT_INTERFACE`（硬错误）|
| C1 | 每个 `## NN.` 下至少 1 个 `###`（无上限） | 0 个等于该界面无意义 |
| C2 | 设计总览以外的每个 `###` 下方第一行必须是 `@角色1 @角色2 ...` | 空格分隔，至少 1 个角色 |
| G1 | `####` 子分类标题只能出现在 `###` 内部 | `#### ` 出现在 `## NN.` 直属内容区（`###` 之前）→ `H_H4_ORPHAN` |
| G2 | `####` 标题长度 ≤ 24 显示宽度（中文字 ≤ 12 个） | 超长 → `H_GROUP_TITLE_LEN_OVERFLOW` |
| G3 | 同一 `###` 簇内 `####` 标题不可重复 | 大小写不敏感 → `H_GROUP_TITLE_DUPLICATE` |

## 软约束（违反 → 引擎给出提醒，不阻断）

| ID | 规则 | 说明 |
|---|---|---|
| W1 | `@角色` 必须从 7 个角色名单里选 | 见 `role-tags.md` |
| **W2** | **`###` / `####` 命名禁用死分类词** | 完全相等 OR endsWith 命中：`显示规则 / 操作规则 / 反馈表现 / 异常与边界 / 功能定位 / 配图说明 / 注意事项 / 待确认`；理由：死分类把多个功能的同类规则拍平到一起，与"按界面信息块分类"原则相违 → `W2_DEAD_CATEGORY_CLUSTER_NAME` |
| **W6** | **`###` / `####` 命名应为名词性界面信息块或行为单元，避免规则属性后缀** | 名词正例："基础信息" / "出售按钮" / "hover 触发区"；行为单元正例（找不到 UI 名词时）："hover 行为" / "折叠流程"。endsWith 命中下列后缀 → `W_CLUSTER_NAME_LOOKS_RULE`：`时机 / 规则 / 层级 / 限制 / 边界 / 兼容 / 表现`。同时命中 W2 与 W6 时只 emit W2（更严格）|
| W3 | `- 配图：xxx` 紧跟它所说明的那条规则，**位置即语义**；一簇允许多张；状态类簇优先一态一图 | 只在确实需要局部图时加。引擎按 bullet 顺序原位渲染每条配图占位 |
| W4 | bullet 粒度 = **完整行为叙述**：同一控件的常规规则合并为一条含多动作串联的流畅叙述；需要强调 / 有风险 / 需执行角色特别注意的点独立成条 | 见下方"转写文体规范" |
| W5 | `####` 之前有游离 bullet → 建议全分组或全不分 | 混用时 parser emit `W3_CLUSTER_MIXED_FREE_BULLETS_AND_GROUPS`，不阻塞 |
| W7 | 同组内状态行连续书写 | 状态行之间夹着普通规则 → `V2_W_STATE_LINES_SCATTERED`（`配图：` 不算隔断）；见 T9 |
| W8 | 状态行不用 `状态·` / `状态｜` 前缀 | 命中 → `V2_W_LEGACY_STATE_PREFIX`，按普通 bullet 渲染；见 T10 |

## 转写文体规范（LLM 生成时遵守，引擎不校验）

以下规则约束 LLM 把策划稿转写为 v2 Markdown 的文体与内容边界。引擎 parser **不**为此新增校验码；由 Phase 2 自检清单保障。

### T1 — bullet 粒度：完整行为叙述（W4 展开）

- 一条 bullet = 一个**完整行为叙述**，同一控件的常规规则合并为一条，可含多动作串联
- 需要强调、有风险、或需执行角色特别注意的点**独立成条**
- ❌ 旧原子化风格（禁止）：

  ```
  - W/A/S/D 四键移动角色
  - 按住 Shift 加速跑
  - 按空格跳
  - 滑动鼠标转动镜头视角
  ```

- ✅ 完整行为叙述（正确）：

  ```
  - W/A/S/D 四键移动角色，按住 Shift 加速跑，按空格跳，滑动鼠标转动镜头视角
  - 按住左键锁定朝向：按住期间移动不改变角色朝向，按住期间顶部显示 toast 提示"朝向锁定中…"
  ```

- ✅ 强调点独立成条（正确）：

  ```
  - 需要注意，按下 R 呼出动作条时，光标从当前选中动作位置处出现
  ```

### T2 — 图上不可见的内容不进簇

簇内容仅包含在章节主图上**有可指认 UI 锚点**的规则。下列四类内容不写入簇（丢弃决策的产生与用户确认流程走 Phase 2 Step 0.3"归位 + 显式丢弃清单"，禁止静默丢弃）：

1. **纯服务端规则且无 UI 表现**——持续时间、解除条件、并发裁决等由服务端控制、界面仅同步结果的规则。如确有必要说明，在设计总览一句话带过
   - ❌ `- 泡泡持续时间等数值由服务端控制`
   - ❌ `- 押送解除条件由服务端控制，解除后被泡者恢复自由`
2. **纯环境演出**——无控件可指的演出效果
   - ❌ `- 高度到达 400 米时天空盒切换为宇宙星空`
3. **预留不开发的交互**
   - ❌ `- 点按方向键只位移不转朝向为预留交互，本版本不开发`
4. **开关 / 状态的反面显然陈述**——与正面陈述互为镜像的内容
   - ❌ 已写 `- 开启时进入绘制画面自动铺底色` 后，再写 `- 关闭时保持当前颜色，不铺底色`

### T3 — 同一控件的规则跨簇归位合并

同一 UI 控件的规则集中在该控件所属的**一个簇**内，不按策划稿段落结构分裂到多个簇。

- ❌ 策划稿在"操作方式"段写"F 键释放换色冲刺技能"、在"HUD 说明"段写"右下技能按钮显示冷却"，转写时拆成 `### 口哨与技能` + `### 技能占位按钮` 两簇
- ✅ 两处规则合并进 `### 技能占位按钮` 一个簇

### T4 — 术语跟随设计稿实际文案

控件名 / 状态名优先采用设计稿（草稿、截图、Figma 成品）上**实际出现的文案**，而非策划稿内部术语或 LLM 自造术语。冲突时以设计稿为准。

- ✅ 策划稿写"警官蛋徽章"、设计稿文案为"治安官" → 用"治安官"
- ✅ LLM 惯用"pill 按钮"、设计稿标注"按钮" → 用"按钮"

### T5 — UI 反馈补全

写每个控件簇时自问：**该操作 / 状态有没有可见反馈？** 策划稿未写明时，按交互常识补一条反馈描述（toast / 浮显 / 高亮 / 音效等），以正常陈述语气写入 bullet，**不加"待确认"类标记**——反馈补全是转写完整性的一部分，属设计师职责范围内的主动拍板，不是开放问题。

- ✅ 策划稿只写"按住左键进入锁定朝向" → 补 `- 按住左键锁定朝向：按住期间移动不改变角色朝向，按住期间顶部显示 toast 提示"朝向锁定中…"`
- 策划稿已写明反馈（如"落地触发烟花特效"且图上有可见表现）→ 直接转写，不重复补

### T6 — 只写设计稿看不出来的信息增量

判据：对每条 bullet 自问——**看主图 / 配图能不能直接得出这句？** 能 → 删。bullet 只承载图上看不出来的东西：交互行为、状态切换、边界条件、配表分工、动效时机与曲线。

下列内容不写：

1. **设计稿肉眼可见的静态信息**——位置、排列方向、行数、颜色、图标样式。若与不可见约束绑定（对齐方式、配表来源），只写该约束
   - ❌ `- 位于屏幕左下，固定 5 行，每行左侧为按键图标、右侧为操作名称`
   - ✅ `- 位于屏幕左下，每行左侧为按键图标、右侧为操作名称，键位由策划配表，底对齐`
2. **穷举式范围声明**——界面清单本身就在文档里，穷举制造维护负担
   - ❌ `- 除房主设置房间面板、地图选择界面、ESC设置面板、F1说明面板外，所有界面常驻显示`
3. **描述占位物本身的句子**——占位文案是过程产物
   - ❌ `- 当前稿统一为 X 操作名称 占位文案，实际键位与文案待定稿`
4. **逐条列举的参数 / 数值清单**——收束为一句配表分工
   - ❌ 参数名 + 默认值逐条列 8 条
   - ✅ `- 参数逐行竖向排列，每行左侧为参数名、右侧为当前值，具体控件参数策划配表即可`

**簇 bullet 数目标 3–6 条**（不含 `配图：`）。超过 6 条大概率混入了可见信息——先按 T6 / T7 删减、按 T8 合并动效，仍超过且能明确分类时才用 `####`。

### T7 — 同簇同义 bullet 合并

同一 `###` 簇内语义重复的 bullet 合并为一条。典型：普通规则与同义的状态行重复。

- ❌
  ```
  - 猎人获胜时显示 `猎人获胜！`
  - 猎人胜利状态：猎人获胜时进入
  ```
- ✅ 只保留一条

### T8 — 动效句：直接说，先情况后动效

动效 bullet 不加任何前缀，直接写成一句话：

```
- [什么情况下]，[需要什么样的动效]
```

- **前半句写情况**：哪个时机、什么事件触发，如"选中卡片时""阶段切换时""分数增加时"
- **后半句写动效**：谁动、怎么变、什么节奏，如"卡片放大回弹，先快后慢"
- **不写 `动效需求：` 前缀**，也不用冒号——冒号格式只留给状态行（T10），两者靠格式就能区分

两半缺一不可，并满足：

1. **同类合并**——同簇内数字类 / 头像类 / 按钮类等同类元素的动效合并为一条，情况并列写在前半句
   - ❌
     ```
     - 躲藏分数增加时，对应数字滚动
     - 击杀数增加时，对应数字滚动
     ```
   - ✅ `- 躲藏分数或击杀数增加时，对应数字快速滚动后减速落定`
2. **显隐双链路**——有出现/隐藏变化的 UI，出现与隐藏两种情况都要写
   - ✅ `- 阶段切换时，阶段名与倒计时整体淡出后再淡入；结算时整体淡出隐藏`
3. **禁止空句**——后半句不写"形式待定 / 节奏由策划配置"；按交互常识直接给出变化与节奏（与 T5 同属设计师主动拍板，不加待确认标记）
   - ❌ `- 抽选开始时，头像逐个高亮，节奏由策划配置`
   - ✅ `- 抽选开始时，头像逐个高亮，速度由快到慢，不要匀速`
4. **先情况后动效，不倒装**
   - ❌ `- 卡片放大回弹，在选中时播放`
   - ✅ `- 选中卡片时，卡片放大回弹，先快后慢`
5. **不加前缀**
   - ❌ `- 动效需求：选中卡片时，卡片放大回弹，先快后慢`
   - ✅ `- 选中卡片时，卡片放大回弹，先快后慢`

**与状态行（T10）的区别**：

| | 状态行 | 动效句 |
|---|---|---|
| 格式 | `[名字]状态：[出现条件]` 或只写 `[名字]状态` | 一句话，无前缀、无冒号 |
| 写什么 | 什么情况下进入 / 退出这个状态 | 先写什么情况，再写需要什么样的动效 |
| 不写 | 外观（交给配图）、动效（交给动效句） | 静态外观（交给配图） |
| 渲染 | 状态名加粗 | 常规字重 |

同一件事既有状态又有动效时，拆成两条：

- ❌ `- 选中状态：点击卡片后进入，卡片放大回弹`
- ✅
  ```
  - 选中状态：点击卡片后进入
  - 进入选中状态时，卡片放大回弹，先快后慢
  ```

### T9 — 簇内叙述顺序

每个 `###` 簇（有 `####` 时为每个分组）按下面四段顺序写，没有内容的段直接跳过：

| 段 | 写什么 | 不写什么 |
|---|---|---|
| ① 是什么 | 作用、何时出现、数据来源 | 设计稿可见的位置与外观（T6） |
| ② 怎么交互 | 操作 → 直接结果；不形成状态的边界情况（如资源不足弹 toast）紧跟触发它的交互 | |
| ③ 有哪些状态 | 状态行（T10）；冷却、锁定、为空等能写成状态的边界情况归到这里 | |
| ④ 反馈 | toast / 音效 / 特效；动效句（T8）放在最后 | |

`配图：` 跟随它说明的那条 bullet，不改变所在段。纯展示的簇（如分数 HUD）通常只有 ①③④。

- ❌ 顺序散乱
  ```
  - 选中状态：点击卡片后进入
  - 展示可选地图，数据由策划配表
  - 选中卡片时，卡片放大回弹，先快后慢
  - 点击卡片选中该地图
  ```
- ✅
  ```
  - 展示可选地图，数据由策划配表
  - 点击卡片选中该地图，同时取消其他卡片的选中
  - 默认状态
  - 配图：卡片默认态
  - 选中状态：点击卡片后进入
  - 配图：卡片选中态
  - 选中卡片时，卡片放大回弹，先快后慢
  ```

引擎只检查能机械判断的一点：状态行连续（W7）。动效句没有前缀，引擎认不出来，放在末尾靠写作时自查。

### T10 — 状态行写法

```
- [名字]状态：[什么情况下出现 / 如何退出]
- [名字]状态                     ← 简单状态只写名字
- 配图：[该状态的截图]            ← 可选，单独一行紧跟状态行
```

1. 冒号后写**出现条件**，不写外观——外观交给配图
   - ❌ `- 选中状态：外围显示青色描边`
   - ✅ `- 选中状态：点击卡片后进入，其他卡片同时取消选中`
2. 简单状态（默认态等）不写冒号和条件
   - ✅ `- 默认状态`
3. 不写 `状态·` / `状态｜` 前缀，不用 `·`
   - ❌ `- 状态·冷却：技能释放后`
   - ✅ `- 冷却状态：技能释放后进入，冷却结束恢复默认`
4. 不写动效——进入/退出时的动效另起一条动效句（T8，无前缀）
   - ❌ `- 冷却状态：技能释放后进入，按钮转圈遮罩`
   - ✅ `- 冷却状态：技能释放后进入，冷却结束恢复默认` + `- 冷却中，按钮遮罩顺时针匀速转出`

**引擎识别规则**：冒号前的部分（无冒号则整行）以"状态"结尾、3–10 个字、不含 `，。；、` 等标点 → 状态行，渲染时状态名加粗。普通句子如"进入战斗状态后顶部显示血条"不会被识别。

### 配图原位示例（W3 展开）

`配图：` 紧跟它所说明的规则，一簇可多张：

```markdown
### 阶段与倒计时
@程序 @GUI @动效

- 阶段名位于屏幕顶部居中，倒计时数字位于阶段名左侧
- 配图：阶段名与倒计时位置
- 结算阶段隐藏阶段名，仅保留倒计时数字并居中显示
- 配图：结算态倒计时居中
- 准备阶段与猎人抽选阶段不显示倒计时数字
- 配图：准备阶段无倒计时
```

状态类簇一态一图（状态行写法见 T10）：

```markdown
### 地图卡片
@程序 @GUI

- 默认状态
- 配图：卡片默认态
- 悬停状态：鼠标移入卡片时
- 配图：卡片悬停态
- 选中状态：点击卡片后进入，其他卡片同时取消选中
- 配图：卡片选中态
```

## 簇内子分类小标题（`####`，可选）

当一个 `### 语义簇` 的 bullets 较多且能分类时，可以在簇内用 `####` 把 bullets 切成若干组。**先按 T6 / T7 / T8 删减合并**——超过 6 条通常说明混入了可见信息或同义条目；删减后仍超过 6 条且能明确分类，才用 `####`：

```markdown
### 经验条
@程序 @GUI @动效

#### 基础信息
- 当前等级标签右侧显示一条黄色进度条
- 展示玩家当前等级的经验进度

#### 升级反馈
- 经验条满格时触发升级特效（爆发光效）
- 当局连升多级时，升级特效循环播放
- 满级时经验条显示为满格静止状态
```

**规则**：

- `####` 是**软约束**，不要求所有簇都分组，视内容粒度决定
- 一个簇可以有 0、1 或多个 `####`
- 分组名长度 ≤ 12 个中文字（显示宽度 ≤ 24）
- 同一簇内 `####` 标题不可重复
- `####` 必须出现在 `### 语义簇` 内部，**不能**在 `## NN.` 直属范围（没有 `###` 时直接写 `####` → 硬错误）
- 建议要么全分组、要么全不分，避免"游离 bullets + ####"混用（会产生软警告）

## 章节内气泡编号规则（关键）

- 每个 `## NN. [界面名称]` 自带一张主图（全局规范章节例外）
- 该章节内 `###` 的序号（1, 2, 3, ...）= 该图上对应气泡的编号
- **章节内连号，不全局连号**
- 例：`## 01.` 内有 5 个 `###` → 该图上有气泡 1、2、3、4、5；`## 02.` 内有 8 个 `###` → 该图上有气泡 1、2、3、4、5、6、7、8（重新从 1 开始）

## 全局规范章节（自动识别）

章节名命中关键词 **`全局 / 规范 / 组件 / 汇总`** 的 `## NN.`，被引擎识别为"全局规范章节"。例：

- `## 03. 等级数字全局展示`
- `## 04. 按钮组件规范汇总`

对这类章节，引擎行为：

- ❌ 不索要主图（Phase 3 自动跳过该章节）
- ❌ 不在模板上保留主图占位 / 占位文案
- ❌ 不布气泡（`气泡` FRAME 被整体删除）
- ✅ 右栏 `说明块` 正常渲染 `### 语义簇`

如果一个章节确实要展示一组组件而不关联一张具体界面图，用这些关键词命名即可；否则请补一张主图（哪怕是多图拼贴的汇总图）。

> **注意**：S3 章节命名校验的"全局规范白名单"含 `流程 / 结算`，比 isGlobalSpec 多 2 个词。`流程 / 结算` 章节 S3 通过但**仍要主图**（不自动跳过 Phase 3），按普通界面章节渲染。

## 多态拆分指南（指引性条款，非强校验）

当一个需求涉及同一功能的多种界面态（hover 前/后、普通/选中、默认/锁定 等），按下列规则决定拆 1 个章节还是 N 个章节：

- 两态之间**功能模块差异 ≥ 2-3 个**（新增 / 移除 / 重命名的可识别信息块）→ **拆 N 个章节**，每态对应 1 个章节
- 否则 → **合 1 个章节**，态差异通过簇 / 子分类 / 对比图表达

**示例**：

| 场景 | 模块差异 | 决策 |
|---|---|---|
| 战场天书暗灰条态（1 元素）vs 展开态（顶部信息条 + 5 卡 + 锁按钮 + 使君形象 = 4 模块）| ≈ 4 | 拆 2 章节 |
| 按钮默认态 vs 按下态（仅视觉差异，无新增模块）| 0 | 合 1 章节，簇内 bullet 写两态规则 |
| hover 前（暗灰触发区）vs hover 后（5 卡面板）| ≈ 3 | 拆 2 章节 |

LLM 在 Phase 2 Step 0.1 输出界面清单时，**必须显式标注**多态的拆 / 合决策与一句理由。
