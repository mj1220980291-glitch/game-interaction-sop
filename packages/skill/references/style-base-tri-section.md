## 簇结构约定

`###` 簇名 = 控件 / 信息块名词（`队伍排行栏`、`基础信息`、`阶段与倒计时`）。

簇内结构固定，顺序不可调换：

1. `###` 簇名（控件 / 信息块名词）
2. `@角色...` 行：列出该簇所有相关职能（含正文 `- @职能：` 条目对应的职能，不能漏）
3. `#### 界面信息`
4. `#### 状态`
5. `#### 动效`

三段都有内容才写；无内容则省略该段，但段与段之间相对顺序不变。

**硬规则：`####` 段名一律落在 `@角色` 行之下。** 出现「`#### 界面信息` 在 `@角色` 行之前」= 转写错误，必须把 `@角色` 行提到所有 `####` 之上，不要靠调模板解决。

约束：

- **`structure.require_sections: true` 是本 base 的硬结构**：三段结构覆盖 `markdown-v2-spec.md` 里「`####` 可选、超过 6 条才用」的建议；`####` 本身合法（G1–G3 只限制位置 / 长度 / 重复），分组后不受「3-6 条」建议约束
- **所有 bullet 必须落在某个 `####` 下**，不留游离行（游离 + 分组混用会触发 W5）
- `状态` 段用**常规描述文本**写，不用 bullet 状态行；**一簇只表达一类状态**，三类各占一句（或换行分句），互不揉杂：
  1. 状态枚举：共有哪几种、各叫什么（枚举完整）
  2. 状态关系：谁触发谁、何时切回、切换后停在哪
  3. 空状态与边界情况：无数据、无命中、满员、置灰、失败回退等例外
- **多类并存时的落笔顺序固定**：枚举句 → 关系句 → 空状态和边界情况句。枚举归枚举，别把边界条件挂进枚举句；边界句以「空状态和边界情况：」起头
- `状态` 段命中 ≥ 2 种状态时，**默认追加一条配图占位 bullet**：`- 配图：补状态A、状态B、状态C`，把该簇要补的状态图一次列全
- `动效` 段不写状态行，避免与 T10 混写；段内每条动效都写成 `- @动效：…`
- 三段名 `界面信息` / `状态` / `动效` **已避开 W2 死分类词表**（`显示规则 / 操作规则 / 反馈表现 / 异常与边界 / 功能定位 / 配图说明 / 注意事项 / 待确认`）。一旦出现 `W2_DEAD_CATEGORY_CLUSTER_NAME`，说明段名被改坏，必须改回上表三段名，不要靠忽略警告过关
- **同一对象的描述合并成 1 条 bullet**：同一控件 / 信息块的多个属性与规则，用「；」分隔并换行写进同一条，不要拆成 3–4 条 bullet；也不要为一个控件的不同属性另立小簇（bullet 数与簇数都会拖慢引擎写 Figma）

好：

```markdown
### 队伍排行栏
@程序 @GUI @动效

#### 界面信息
- 位于屏幕右上角，纵向展示 3 支队伍色块栏；左侧为队徽与队伍名次，右侧为 2 名队员头像与个人实时名次
- 本队通栏尺寸更大
- 通关后底板改为黄色

#### 状态
排行栏仅有实时状态：个人名次按路程进度即时排序，队伍名次按每队最后一人的名次排序。

#### 动效
- @动效：个人名次变化时，数字滚动动效，快速滚动后减速落定
```

## 职能标注

- 配表拆着写：表结构、字段、生效逻辑 → `@程序`；具体数值、阈值 → `@策划`
- 触发规则、判定条件 → `@程序`
- 新出资源只写「需要新出什么」，不写怎么用：
  `- @GUI：需要新出 XXX 图标` / `- @美术：需要新出 XXX 场景模型` / `- @音频：需要新出 XXX 音效`
- 一职能一条，不混写；普通 bullet 不夹带职能尾巴

### 顶部 @角色 行必须覆盖簇内所有职能（硬规则）

- 簇名下第一行 `@角色...` 必须列出该簇正文（含子分段 `####` 下）出现的所有 `- @职能：` 条目对应的职能
- 不得出现下方 `- @动效：…` 而顶部漏写 `@动效` 的情况
- 写完一簇做一次扫描：顶部角色集合 ⊇ 正文出现的职能集合

### 同簇内同一职能多条合并（硬规则）

- 同一簇（含同一 `####` 子分段）内有 ≥ 2 条属于同一职能的 bullet 时，必须合并成一条
- 格式：`- @职能：` 作为头，换行后 2 空格缩进 `1.`/`2.`/`3.` 编号列表
- 示例：
  ```markdown
  - @程序：
    1. 刷新冷却 3 秒，冷却期间按钮置灰
    2. 刷新失败弹toast：网络连接失败，请重试
  ```
- 单条职能条目仍写一行 `- @职能：…`，不强行加编号

## 句子与标点

- 一条 bullet 内的多个分句在「；」后回车换行，续行缩进两格、不写 `- `，条末也用「；」收尾
- 同一对象的多个属性合并成一条 bullet，合并后每句单独成行，不并成一大段
- 正确写法：

```markdown
- 纵向列表展示房间，一屏可见 7 行，超出可滚动；
  每行含缩略图、房间名、房间状态、当前人数/人数上限；
  行内以信号图标表示房间网络状态；
  点击任意行选中该房间，右侧详情面板同步切换；
```

## 反馈写法

- 拦截或成功反馈统一写成「弹toast：<文案>」，作为 `@程序` 条目

## 资源与背景（@GUI）

- 先写一句背景或所属玩法约束，再写需要出的资源
- 资源按「需要出 N 个：A、B、C」列举，状态数与图标数都算资源

## 多按钮差异

- 多个按钮逻辑不同时，用【按钮名】分条对比，各写各自的启用与判定条件

## 配图规则（多状态与动效）

- 按钮状态、资源状态存在多状态时，默认补图：在该条规则下方插 `- 配图：补状态A、状态B、状态C`，状态名与 `状态` 段枚举一致；
- 有动效时需要补图：在 `动效` 段末插 `- 配图：补动效图`；
- 同一组件有几个状态就补几格，不把状态拆成额外簇；
- 占位画框：背景 `#FFFFFF`、不透明度 `10%`；框内文字统一写「配图占位：补状态A、状态B、状态C…」，与 `- 配图：` 条目列举的状态逐个对应，设计按框内文案直接替换成状态图。

## 动效写法

句式：`- @动效：[触发情况]，[效果]，[节奏]`

- 所有动效一律写成职能条目 `- @动效：…`，`动效` 段内不留无前缀的动效 bullet
- 触发情况用一句从句写清（「个人名次变化时」「阶段切换时」「GO 出现时」）
- `渐入动效` / `渐出动效` / `循环动效` 是常用候选，不是封闭词表；不贴切时直接写情况
- 效果词两到四字 + 「动效」：晃动动效、刷光动效、缩放动效、飘字动效、滚动动效、呼吸动效
- 同类合并，先情况后效果，不写「动效需求：」，不写「节奏由策划配置」

好：`- @动效：个人名次变化时，数字滚动动效，快速滚动后减速落定`
坏：`- 动效需求：数字要滚动，节奏由策划配置`

## 红点规则

四要素缺一不可：

- 触发条件：什么情况下出红点
- 红点样式：新 / 感叹号 / 数量
- 穿透路径：手写全链路，如 `tab-系统菜单页-esc入口`
- 消除方式：点击消除 / 浏览消除

好：`- 红点样式：数量。穿透路径：系统菜单-邮箱入口。消除方式：点击消除`

## 简练与去重

- 一个设计点只描述一次，落在最相关的那一段；其他段不重复提及
- 跨段不复述：`界面信息` 写过位置与构成，`状态` 不再重述外观
- 总览段只写结论与范围，不复述簇内规则
- 同一控件在多个簇出现时，只在主簇展开，其余簇一句带过
- 判断标准：删掉该句后，读者是否仍能从文档里得到同样信息；能删则删

## 结构偏好

- 簇名（`###`）名词化：控件 / 信息块名词（`队伍排行栏`、`基础信息`、`阶段与倒计时`），不写「xx规则 / xx说明」这类规则属性名
- 三段强制：每簇必须按 `#### 界面信息` → `#### 状态` → `#### 动效` 顺序出现，无内容的段直接省略，不挪顺序、不改段名、不留第四段；三段一律在 `@角色` 行之下
- 每段所有 bullet 必须落在该 `####` 下，不留游离 bullet（游离 + 分组混用触发 W5）
- `状态` 段写描述文本，一簇只讲一类状态（枚举 / 关系 / 空状态与边界，分句换行），不写 `xx状态：出现条件` 这类状态行
- `状态` 段命中 ≥ 2 种状态时默认带一条 `- 配图：补状态A、状态B、状态C`
- 动效一律 `- @动效：…` 独立条目，全部落在 `动效` 段，不在 `界面信息` / `状态` 段里夹带动效句
- `- 配图：…` 放在它说明的段内、紧跟对应规则；`动效` 段的配图写在段末
- `- @职能：…` 紧挨它说明的规则，段尾落位；与规则无关的通用流程不标职能

## 示例

好：

```markdown
### 刷新按钮
@程序 @GUI @动效

#### 界面信息
- 位于顶部操作区右侧，图标按钮，点击整表重新拉取；刷新期间按钮置灰不可重复点击

#### 状态
刷新按钮共有 2 种状态：默认状态、刷新中状态；
  默认状态点击后进入刷新中状态，拉取完成后回到默认状态；
  空状态和边界情况：拉取失败时回到默认状态，列表保持刷新前内容。
- 配图：补默认态、刷新中态

#### 动效
- @动效：刷新中图标匀速转动，刷新完成后停转并轻微回弹
- 配图：补刷新转动动效图
```

坏：

```markdown
### 刷新按钮的显示规则

- 点刷新会重新拉列表，刷新中按钮变灰（无 `####` 分段、无状态说明、动效埋在正文里）
- 刷新状态：刷新中
```
（坏例三处问题：簇名带规则后缀、三段全无、动效句混进 `界面信息`）
